# SparkPanel headless — панель в одном Docker-образе

Цель — чтобы любой поднял SparkPanel у себя одной командой и спокойно обновлял её:
сайт читает данные через внешнее API (`/api/v1`), ассистенты пишут через MCP
(`/api/mcp`), а сама панель — один контейнер рядом с базой.

В этой папке — всё, что относится к такой поставке: образ, пример `docker-compose.yml`
для того, кто ставит, шаблон секретов и этот файл. Наша разработка (`docker/`,
`scripts/dev.sh`) и наш прод (`prod/`) отсюда ничего не берут и не меняются.

## Как устроен образ

```
                    один контейнер, порт 3000
┌──────────────────────────────────────────────────────────┐
│ NestJS                                                   │
│   /api/…   → контроллеры, как сейчас                     │
│   /admin…  → фронтенд статикой (HTML + JS из next build) │
│   /        → редирект на /admin                          │
└──────────────────────────────────────────────────────────┘
         │                         │
     Postgres                    MinIO (файлы)
```

- **Фронтенд — статикой.** Серверного рендеринга в панели нет: ни `getServerSideProps`,
  ни API-маршрутов Next, ни `middleware`, все данные грузятся в браузере после входа.
  Поэтому `next build` с `NEXT_OUTPUT=export` (`frontend/next.config.js`) выгружает
  панель в `out/` — около 9 МБ HTML и JS, — и её отдаёт сам NestJS.
  Сервер Next в образе не нужен: на один процесс Node меньше, а панель и API
  по-прежнему на одном адресе — CORS не нужен, относительные `/api`-пути работают.
- **Раздача** — `backend/src/frontend/serve-frontend.ts`, включается переменной
  `FRONTEND_DIR` (в образе — `/app/frontend`). Страница — файл `<адрес>.html`;
  динамические страницы Next выгружает по одной на маршрут
  (`admin/contents/[contentId].html`, `admin/files/[sectionId].html`), номер из адреса
  страница берёт сама в браузере. Список страниц читается при старте. Неизвестный
  адрес — `404.html` с кодом 404. Файлы сборки (`/_next/static/…`, в имени хэш)
  кешируются навсегда, HTML — `no-cache`.
- **Стили antd** собираются при `next build` (`pages/_document.tsx`) и лежат в HTML —
  проверено на выгрузке.
- **Сборка** — два независимых этапа (фронтенд, бэкенд), Docker гоняет их параллельно
  и кеширует по отдельности. Node 22.

Локально ничего не поменялось: `next dev` (:3401) за nginx (:3400), как раньше.
Без `NEXT_OUTPUT` конфиг Next прежний, без `FRONTEND_DIR` бэкенд статику не отдаёт.

## Собрать и запустить

```bash
cd webSite/headless
cp .env.example .env      # и заменить значения
docker compose up -d --build
```

Панель — `http://localhost:3000`. Первым входом заводится главный администратор.

## Переменные

Все — в `environment:` у `sparkpanel` в `docker-compose.yml`, секреты — из `.env`.

| Переменная | Назначение |
|------------|-----------|
| `DATABASE_URL` | база одной строкой: `postgres://user:pass@host:5432/db`, TLS — `?sslmode=require` (сертификат проверяется; самоподписанный — `?sslmode=no-verify`). Спецсимволы в пароле — URL-кодом (`@` → `%40`). Без неё читаются пять `POSTGRES_*` (`HOST`, `PORT`, `USER`, `PASSWORD`, `DB`), как в нашей разработке |
| `PUBLIC_URL` | внешний адрес панели (`https://cms.example.com`): из него полные адреса файлов во внешнем API и `servers` спецификации. Не задан — адрес из запроса (`Host` + `X-Forwarded-Proto` от прокси) |
| `PRIVATE_KEY` | подпись входа в панель (JWT) |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | встроенное хранилище файлов (MinIO из того же compose) |
| `FRONTEND_DIR` | папка статики панели; в образе уже задана (`/app/frontend`) |

Своя база вместо сервиса `postgres` — заменить `DATABASE_URL` на её адрес и убрать
`postgres` из compose (вместе с `depends_on`).

Только образ, без запуска: `cd webSite && docker build -f headless/Dockerfile -t sparkpanel:dev .`

**Статику не собирать в рабочей папке `frontend/`.** Промежуточная сборка Next пишет
в `.next` и затирает кеш работающего `next dev` (тот отвечает 500, лечится
`rm -rf .next` и перезапуском); `distDir` меняет только каталог выгрузки, не сборки.
Поэтому статика собирается в Docker, а для пробы — в копии папки.

## Решения, которые ещё не приняты

1. **Встроенное хранилище файлов.** Папка на диске (`/data/uploads` в томе, файлы
   отдаёт сама панель; установка — панель + Postgres, S3 по желанию в «Настройках →
   Хранилища») или MinIO, как сейчас (три сервиса, `/uploads` придётся проксировать
   через NestJS). Предложение — диск.

Решено: первичная настройка остаётся как есть — главного администратора создаёт
первый, кто откроет `/admin` (поставил — сразу зайди). Репозиторий публичный — `github.com/xvandevx/sparkpanel`, один на фронтенд и бэкенд, лицензия — BSL 1.1
([`LICENSE`](../../LICENSE)). Образ выпускает `.github/workflows/image.yml` только по тегу
`v*.*.*` (или кнопкой «Run workflow» — собрать без выпуска) в GHCR (`ghcr.io/xvandevx/sparkpanel`), Docker Hub — вторым адресом позже.
