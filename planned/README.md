# planned — планируемый функционал

Что нужно сделать. Эту папку ведёт заказчик: один файл на задачу или модуль.

## Как писать

Имя файла — `<модуль>.md` (`pages.md`, `media.md`, `seo.md`). Формат свободный, но чем
конкретнее — тем меньше уточняющих вопросов. Полезно указать:

- **что делаем** и зачем — какую задачу пользователя закрывает;
- **как это выглядит** — экраны, поля, кнопки, поведение;
- **правила** — что запрещено, что обязательно, что происходит в пограничных случаях;
- **что НЕ входит** в задачу — чтобы не разрослась.

Если чего-то не хватает, я не додумываю молча: задаю вопрос либо фиксирую допущение в
`implemented/` при сдаче.

## Жизненный цикл

```
planned/<модуль>.md  →  реализация  →  implemented/<модуль>.md  +  docs/<модуль>.md
```

Файл из `planned/` после реализации удаляется: что сделано — описано в `implemented/`,
как это работает — в `docs/`. Частично сделанное остаётся здесь с пометкой, что уже готово.
