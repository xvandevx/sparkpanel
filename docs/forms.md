# Формы обратной связи

> **Во фронтенде раздел скрыт.** Пункта меню и страниц `/admin/forms*` в панели нет:
> экраны, логика и сетевой слой лежат в `webSite/frontend/to_delete/feedback/` (как
> вернуть — README там же). Бэкенд, таблицы и API ниже работают как описано, с одним
> исключением: в выборе списка для привязки к контенту (`link-sources`) форм и полей
> форм нет — к ним не привязать новое свойство. Вернуть — две строки в `findSources`
> (`infoblocks/settings/links/link-targets.service.ts`).

Раздел меню **«Обратная связь»** — формы, которые панель отдаёт сайту, и их поля —
вопросы посетителю. Это два списка [нового редактора контента](../webSite/frontend/CLAUDE.md):

- **«Формы»** (`/admin/forms`, ключ списка `forms`) — код, название, активность;
- **«Поля форм»** (`/admin/forms/fields`, ключ `form-fields`) — тоже только стандартное:
  код, название, активность. Плейсхолдер — системное свойство списка.

Поле **не принадлежит** форме. Форме поля подключают **системным свойством «Поля»** —
множественной привязкой к контенту из списка полей. Поэтому одно поле («Телефон»)
стоит в скольких угодно формах, а порядок полей в форме — порядок значений свойства.

Формы и поля — **контент сайта, общий на всех**, кто им управляет: владельца у них нет,
как у файлов и доменов. Оба списка общие (`isShared`): их настройки и свойства одни
на сайт. Своего экрана раздел не пишет: каждый экран называет код списка и отдаёт Api.

## Модель данных

### `infoblock_forms` — форма

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `SERIAL` | порядковый номер; виден в админке |
| `code` | `STRING` | код, которым форму подключают на сайте (`feedback`) |
| `name` | `STRING` | название для админки |
| `isActive` | `BOOLEAN` | неактивная форма остаётся в админке, но на сайт не попадает |
| `sort` | `INTEGER`, по умолчанию 500 | «Сортировка»: чем меньше, тем выше в списке |

Индекс: `infoblock_forms_code` (`UNIQUE (code)`).

### `infoblock_forms_fields` — поле формы

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `SERIAL` | |
| `code` | `STRING` | имя значения в заявке и в письме (`phone`) |
| `name` | `STRING` | подпись поля на сайте |
| `isActive` | `BOOLEAN` | неактивное поле не показывается ни в одной форме |
| `sort` | `INTEGER`, по умолчанию 500 | «Сортировка»: чем меньше, тем выше в списке |

Индекс: `infoblock_forms_fields_code` (`UNIQUE (code)`).

### Системные свойства

Заводит сервер (`infoblocks/settings/properties/system-properties.ts`, сверяет с базой
`SystemPropertiesService` при каждом старте), через API они не меняются и не удаляются.
Значения правятся в карточке записи, как у любого свойства, и лежат в `infoblock_values`.

| Список | Код | Название | Тип | Значение |
|--------|-----|----------|-----|----------|
| `forms` | `fields` | Поля | привязка к контенту, множественная, `linkList: 'form-fields'` | `[{ listKey: 'form-fields', recordId: '2' }, …]` в `json` |
| `form-fields` | `placeholder` | Плейсхолдер | строка | текст в пустом поле — в `text` |

Всё остальное — получатель заявок у формы, тип и обязательность у поля и прочее —
заводится обычными **свойствами списка** в «Настройках списка». Свойства списка `forms`,
заведённые ещё старым редактором (документы, связанная страница, срок ответа,
«Кто обрабатывает», метка в CRM), стали общими вместе со списком.

Прежняя схема (поле принадлежит одной форме, таблицы `forms` и `form_fields`) лежит
в `to_delete/forms/`. Её таблицы с данными в базе остались нетронутыми: новые списки
пишут в свои таблицы, иначе приведение схемы к новым моделям стёрло бы старые колонки.

## API

Все маршруты требуют авторизации. Владельца у записей нет — фильтра по `userId` тоже;
автор правки для журнала берётся из JWT.

| Метод | Путь | Что делает |
|-------|------|-----------|
| `GET` | `/api/infoblocks/forms` | Формы по сортировке, затем по алфавиту (`FormDto[]`) |
| `POST` | `/api/infoblocks/forms` | Завести форму |
| `PATCH` | `/api/infoblocks/forms/:id` | Изменить форму |
| `DELETE` | `/api/infoblocks/forms/:id` | Удалить форму вместе со значениями её свойств |
| `GET` | `/api/infoblocks/forms/fields` | Поля по сортировке, затем по алфавиту (`FormFieldDto[]`) |
| `POST` | `/api/infoblocks/forms/fields` | Завести поле |
| `PATCH` | `/api/infoblocks/forms/fields/:id` | Изменить поле |
| `DELETE` | `/api/infoblocks/forms/fields/:id` | Удалить поле, не подключённое ни к одной форме |

Значения свойств — общим маршрутом: поля формы —
`PATCH /api/infoblocks/forms/values/:formId`, плейсхолдер поля —
`PATCH /api/infoblocks/form-fields/values/:fieldId`; это делает карточка сама.
Журнал — `/api/infoblocks/history/forms` и `/api/infoblocks/history/form-fields`; правка пишется под её автором
(как у ролей), поэтому журнал показывает каждому его собственные правки.

`FormDto` и `FormFieldDto` отдают `isBlocked`: запись выбрана в чьей-то привязке
к контенту и удалить её нельзя.

Коды ответов: `400` — не прошла проверка DTO (в том числе лишнее поле в теле),
`401` — без токена, `404` — нет такой записи, `409` — код уже занят или запись
подключена и не удаляется.

## Интерфейс

Пункт меню **«Обратная связь»** раскрывается в **«Формы»** и **«Поля форм»**. Полное имя
раздела в меню шириной 232px не помещается; заголовок над таблицей — название
пункта меню.

Таблицы обоих списков — стандартные колонки: название, код, активность. Свойства
(«Поля», «Плейсхолдер» и заведённые вручную) добавляют колонками в шторке «Колонки
таблицы» и фильтруют в строке «Фильтр» над таблицей.

**Карточка формы:** название, код, активность, **«Поля»** — выбор полей из списка
«Поля форм» (порядок выбора — порядок в форме), дальше свойства из настроек списка.

**Карточка поля:** название, код, активность, **«Плейсхолдер»**, дальше свойства
из настроек списка.

Подключённое к форме поле и форма, выбранная в чьей-то привязке, приходят с `isBlocked`:
в строке вместо корзины замок, в карточке нет «Удалить».

У обоих списков в «Настройках списка» закрыты код списка, вложенность (плоский
список) и символьный код («Обязательный и уникальный»).

## Правила и ограничения

- **Коды формы и поля уникальны на сайт** — форму по коду подключают на сайте, код поля —
  имя значения в заявке. Поле подключают к разным формам, и два поля с одним кодом в одной
  форме перепутали бы ответы. Формат обоих кодов: строчные латинские буквы, цифры и дефис
  между ними.
- Уникальность держат **индексы**, а не только проверка: два параллельных сохранения
  прошли бы её оба. Наружу нарушение — `409`.
- **Подключённое поле не удаляется** (`409`): у формы осталась бы ссылка в никуда.
  Сначала поле убирают из форм.
- **Форма, выбранная в привязке другой записи** (страница с формой), не удаляется (`409`).
- **Удаление формы стирает значения её свойств**, в том числе привязки к полям, —
  поля после этого снова можно удалить. Удаление поля стирает его значения (плейсхолдер).
- Привязать можно только существующее поле — иначе `400` «Привязанная запись не найдена».
- Править формы и поля может любой, кто вошёл в панель, а не только главный администратор.

## Чего раздел пока не делает

Панель описывает формы, но **не принимает заявки**: публичного эндпоинта отправки,
хранилища заявок и рассылки писем нет. Менять порядок полей в форме можно только
перевыбором (убрать и добавить заново): перетаскивания в поле привязки нет.

## Настройки

Своих переменных окружения у модуля нет.
