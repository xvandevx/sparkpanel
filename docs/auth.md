# Доступ и учётные записи

Вход в панель по email и паролю, первичная настройка системы (создание главного
администратора) и восстановление сеанса.

## Модель данных

Таблица `users`:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | serial PK | |
| `email` | varchar UNIQUE | логин |
| `passwordHash` | varchar | bcrypt, 10 раундов; наружу не отдаётся никогда |
| `name` | varchar null | отображаемое имя |
| `isRoot` | boolean, по умолчанию `false` | главный администратор |
| `isActive` | boolean | отключённый не может войти |
| `createdAt`, `updatedAt` | timestamptz | |

Индексы:

- `users_email` — UNIQUE по email;
- `users_single_root` — `UNIQUE ("isRoot") WHERE "isRoot" = true`: главный администратор
  в системе **ровно один**, гарантия на уровне БД.

Наружу пользователь отдаётся только через `UserDto` (`id`, `email`, `name`, `isRoot`, `isActive`,
`sort`, …), поэтому хэш пароля физически не может попасть в ответ.

**Токен** — JWT с `{ id, email, isRoot }` (`auth/auth.types.ts`); гард кладёт его в `req.user`,
и права главного администратора сервер проверяет по `req.user.isRoot`. Токен без булева
`isRoot` (выданный до того, как признак стал флагом) гард отвергает — 401 «Сессия устарела —
войдите заново».

## API

| Метод | Назначение | Доступ |
|-------|-----------|--------|
| `GET /api/auth/setup` | `{ needsRoot: boolean, isDevLogin: boolean }` — нужна ли первичная настройка и включён ли вход без пароля | публичный |
| `POST /api/auth/setup` | `{ email, password, name? }` → `{ token, user }`; создаёт главного администратора | публичный, **одноразовый** |
| `POST /api/auth/login` | `{ email, password }` → `{ token, user }` | публичный |
| `GET /api/auth/me` | текущий пользователь по токену | `Authorization: Bearer <token>` |
| `POST /api/auth/dev-login` | → `{ token, user }` главного администратора, без пароля | публичный, **только локально**: `DEV_LOGIN=true` и не `NODE_ENV=production`, иначе 404 |

**Вход без пароля — только для локальной разработки.** На экране входа под «Войти»
кнопка «Войти без пароля (dev)», если сервер сказал `isDevLogin: true`. Нужна, чтобы
разработчик и Claude в панели превью смотрели панель, не набирая пароль. Включает
её флаг `DEV_LOGIN=true` в `backend/.env` (есть в `.env.example`); на проде не работает
дважды — там `NODE_ENV=production` (`prod/docker-compose.yml`) и флага в `prod/.env` нет.

Коды ответов:

| Ситуация | Ответ |
|----------|-------|
| Неверный email или пароль | 401 «Неверный email или пароль» |
| Учётная запись отключена | 401 «Учётная запись отключена» |
| Нет или истёк токен | 401 «Требуется авторизация» / «Сессия недействительна или истекла» |
| Токен старого формата (без `isRoot`) | 401 «Сессия устарела — войдите заново» |
| Повторная первичная настройка | 409 «Учётная запись администратора уже существует» |
| Невалидное тело запроса | 400, массив сообщений по полям |

Все маршруты закрыты по умолчанию: `AuthGuard` подключён глобально (`APP_GUARD`), публичные
помечаются декоратором `@Public()`.

## Интерфейс

Страница `/admin` обслуживает три состояния (решает `components/layout/AdminLayout.tsx`):

1. **Проверка доступа** — пока восстанавливается сеанс.
2. **Настройка системы** — если администратора нет: предупреждение и кнопка «Начать настройку»,
   далее форма (имя, email, пароль от 8 символов, подтверждение). После создания — сразу вход.
3. **Вход в систему** — форма email + пароль.

После входа открывается приложение. Завершение сеанса — в меню учётной записи в шапке.

## Правила

- **Регистрации нет.** Единственный способ завести первую учётную запись — экран первичной
  настройки; после создания администратора эндпоинт отвечает 409.
- **Один и тот же текст ошибки** на «нет такого пользователя» и «неверный пароль» — иначе форма
  входа превращается в проверялку существующих адресов.
- **Пароли:** минимум 6 символов при входе (валидация DTO), минимум 8 — при создании
  администратора.
- **Токен** хранится в cookie `access_token` (SameSite=Lax, 7 дней), передаётся заголовком
  `Authorization: Bearer`. Сеанс восстанавливается запросом `/api/auth/me` при загрузке страницы.

## Настройки

| Переменная | Назначение |
|------------|-----------|
| `PRIVATE_KEY` | секрет подписи JWT (`openssl rand -hex 32`) |
| `JWT_EXPIRES_IN` | срок жизни токена, по умолчанию `7d` |

Сбросить первичную настройку в dev: `DELETE FROM users;` — страница снова предложит создать
администратора.
