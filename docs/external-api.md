# Внешнее API

## Назначение

Сайт и приложения забирают данные панели — страницы, контент, каталог, домены — со всеми
свойствами, а свойства и их значения отдельно, чтобы строить фильтр каталога. Другие
системы — учётная (1С, Битрикс), склад, CRM, сервис синхронизации — по ключу с правом
записи заводят и обновляют записи, в том числе пакетами, и находят свои записи по
**внешнему ID** — номеру записи в системе-источнике. Документация — OpenAPI-спецификация,
которую сервер собирает из настроек списков при каждом запросе, в панели её показывает Scalar.

## Модель данных

`api_keys` — ключи доступа:

| Поле | Что |
|------|-----|
| `id` | номер |
| `userId` | кто создал ключ: API отдаёт данные этого пользователя |
| `name` | для кого ключ |
| `keyHash` | SHA-256 ключа, hex; уникальный индекс `api_keys_key_hash` |
| `keyTail` | последние 4 символа — в списке `sp_••••••••3f9a` |
| `lastUsedAt` | последний запрос; пишется не чаще раза в минуту |
| `isWritable` | право записи; по умолчанию `false` — только чтение |
| `writeLists` | `TEXT[]`: куда ключ пишет — ключи списков (`products`, `content-items.3`); `null` — во все списки API, в том числе в будущие типы контента |

Права задаются при создании и **не меняются**: ключ, ушедший в чужую систему, не получит
больше, чем ему дали. Нужен другой доступ — новый ключ, старый отзывается. Ключи,
созданные до появления записи, — только чтение.

**Внешний ID** записи — колонка `externalId` (`VARCHAR(255)`) в общей строке записи
`infoblock_records` (она одна на все списки и уходит вместе с записью). Уникален внутри
списка: частичный индекс `infoblock_records_external_id` на `(settingsId, externalId)
WHERE externalId IS NOT NULL` — пустые не мешают друг другу. Пишут его только интеграции
(внешнее API, MCP), подробнее — [infoblock-settings.md](infoblock-settings.md).

Сам ключ (`sp_` + 24 случайных байта, base64url) в базе не лежит: его показывают один раз,
в ответе на создание.

## API

### Панель (`/api/external-api`, JWT, только root — `RootOnlyGuard`)

| Метод | Что |
|-------|-----|
| `GET /keys` | ключи, новые сверху |
| `POST /keys` `{ name, isWritable?, writeLists? }` | создать; в ответе `key` — ключ целиком, единственный раз. `writeLists` — ключи списков из `GET /lists`, не пустой; не прислали или `null` — во все. Чужой ключ списка — 400 |
| `GET /lists` | списки API `[{ listKey, name, group, path }]` — из них выбирают, куда ключ пишет |
| `DELETE /keys/:id` | отозвать: ключ сразу перестаёт работать |
| `GET /openapi` | спецификация для вкладки «Документация» |

### Сайт (`/api/v1`, заголовок `X-Api-Key`)

Маршруты помечены `@Public()` (мимо JWT-гарда) и закрыты `ApiKeyGuard`: он находит ключ
по хэшу и кладёт владельца в `req.apiKey`. В Swagger панели их нет (`@ApiExcludeController`).

Списки и их адреса (`api-lists.ts`):

| Адрес | Список панели |
|-------|---------------|
| `/pages` | `pages` |
| `/contents/{код типа}` | `content-items.<номер>` — по списку на активный тип с кодом |
| `/catalog/products` | `products` |
| `/catalog/categories` | `product-categories` |
| `/domains` | `domains` |

Методы у каждого списка:

| Метод | Параметры | Ответ |
|-------|-----------|-------|
| `GET …/items` | `page`, `pageSize` (20/50/100), `search`, `filter[код]`, `sort`, `order`, `parentId` (номер или `root`), `expand`, `domain` | `{ items, total, page, pageSize }` |
| `GET …/items/{idOrCode}` | `expand`, `domain` | запись; 404 |
| `GET …/items/external/{externalId}` | `expand`, `domain` | запись по внешнему ID; 404 |
| `GET …/properties` | — | `[{ code, name, hint, type, isMultiple, isMultiDomain, options? }]` |
| `GET …/facets` | `search`, `filter[код]`, `domain` | `{ код: { type: 'list', values: [{ value, label, count }] } \| { type: 'number', min, max } \| { type: 'content-link', values: [{ list, id, name, count }] } }` |

Ещё: `GET /contents` — типы контента `[{ code, name, path, total }]`;
`GET /pages/by-url?url=&domain=` — страница по полному адресу (слэш в конце не важен);
`GET /domains/by-host?host=` — домен по хосту; `GET /openapi.json` — спецификация.

**Запись в ответе**: поля раздела (`id`, `externalId` — `null`, если не задан, `code`,
`name`, `parentId` у деревьев, `sort`, `createdAt`, `updatedAt`; у страниц `path`, у доменов
`address` вместо кода) и `properties` — объект по коду свойства. Ключ свойства есть всегда: пустое — `null`, у множественного — `[]`.

| Тип свойства | Значение |
|--------------|----------|
| строка, текст, HTML | строка |
| число | число |
| «Список», привязка к значениям списка | код варианта |
| файл, изображение | `{ id, name, url, mimeType, size }`; `url` полный — от адреса запроса |
| привязка к записям и к типу контента | `{ list, id, name }`; с `expand` — связанная запись целиком (ниже) |
| таблица | `string[][]` |
| мультидоменное | значение для `domain` (уникальное домена сильнее общего, «кроме» — `null`); без `domain` — общее |

**Фильтр** `filter[код]`: «Список» — коды вариантов через запятую; привязка — номера записей;
число — `filter[код][gte]` / `[lte]` (или точное значение); строка, текст, HTML — подстрока.
Файл, изображение и таблица не фильтруются (400). **Сортировка** — поля записи и коды
одиночных свойств-строк и чисел; по умолчанию `sort` по возрастанию, равные — новые сверху.

**Раскрытие связей** `expand=categories,brand` — коды свойств-привязок через запятую.
Вместо `{ list, id, name }` у этих свойств приходит связанная запись так, как её отдаёт
`items/{id}` её списка: поля и `properties` по коду, без скрытых свойств, мультидоменные —
для того же `domain`. Одиночная привязка — объект, множественная — массив в прежнем порядке.
Привязка к типу контента раскрывается в тип, как в `GET /contents`: `{ code, name, path, total }`.

- Раскрывают только привязки к спискам, которые API отдаёт (страницы, элементы типов
  контента, товары, категории, домены), и к типам контента. Привязку к ролям или
  пользователям не раскрыть: наружу таких записей нет.
- Связанной записи API не отдаёт (удалена, выключена, не опубликована) — на её месте
  `{ list, id, name }`, как без `expand`.
- **Один уровень**: привязки внутри раскрытой записи — `{ list, id, name }`. Вложенное
  раскрытие не сделано: оно не даром — нужен синтаксис пути (`categories.parent`),
  предел глубины и защита от кольца (товар → категория → товар), а каждый уровень читает
  ещё списки целиком. Нужна запись глубже — второй запрос с её `expand`.
- Связанные записи читаются пачкой: одним чтением на список-источник на запрос, а не
  на привязку, и только те, на которые ссылается страница ответа.
- Непонятное — 400: нет свойства, свойство не привязка, привязка к списку не из API.

### Запись (`/api/v1`, ключ с правом записи)

На тех же адресах списков:

| Метод | Путь | Что | Ответ |
|-------|------|-----|-------|
| `POST` | `…/items` | создать: `{ fields, properties }` | 201 `WriteResult` |
| `PATCH` | `…/items/{idOrCode}` | изменить присланное | `WriteResult` |
| `PUT` | `…/items/external/{externalId}` | upsert: запись с этим внешним ID есть — правится, нет — заводится с ним | `WriteResult` |
| `DELETE` | `…/items/{idOrCode}` | удалить | 204 |
| `DELETE` | `…/items/external/{externalId}` | удалить по внешнему ID | 204 |
| `POST` | `…/items/batch` | пакет upsert: `{ items: [{ externalId, fields, properties }] }`, до 500 | `{ items: WriteResult[] }` |

`WriteResult` — `{ externalId, id, status: 'created' | 'updated' | 'error', error? }`.

- **`fields`** — поля записи: `name`, `code` (если код у списка включён), `isActive`, `sort`,
  у деревьев `parentId` или `parentExternalId` — родитель внешним ID, у создания и правки
  по номеру — ещё `externalId` (пустой или `null` — стереть). У upsert и пакета внешний ID —
  в адресе или в строке пакета, в `fields` — 400. Чего у списка нет — 400 с перечнем,
  что есть. Поля, равные сохранённому, в раздел не уходят.
- **`properties`** — свойства **по коду**: код уникален в списке и не меняется, номер
  свойства у каждой установки свой. Формат значений — как у MCP `save_record`; кроме того:
  «Список» и привязка к значениям списка — **номером или кодом варианта**; привязка
  к записям и к типу контента — номером (`12`), кодом (`"bosch"`) или
  `{ "externalId": "…" }` записи (объектом можно и `{ id }`, `{ code }`, и то, что отдаёт
  чтение, — `{ list, id, name }`); файл и изображение — номер уже загруженного файла.
  `null` стирает значение, неприсланных правка не касается. Неизвестный код свойства или
  варианта — 400 с перечнем. Мультидоменное — группы `{ domainIds, exceptDomainIds?, value }`.
- По коду записи ищут списки с кодом (страницы, товары, категории, элементы типов
  контента, типы контента — для привязки к типу); код у нескольких записей (у страниц он
  уникален только среди соседей) — 409. Записи других списков (роли, формы) в привязке —
  номером или внешним ID.
- Записанное **сразу публикуется**; черновик записи, если он есть, не трогается.
- **Пакет** — по одной записи по порядку; ошибка одной не останавливает остальные,
  результат — по каждой записи в порядке запроса. Запись, заведённая раньше в пакете,
  уже видна следующим: дерево собирается `parentExternalId` одним пакетом.

**Как пишет.** Как и MCP, ключ пишет **маршрутами панели** (`common/panel-client.ts`) от
имени создателя ключа: JWT на минуту с `via: API «название ключа»`. Поэтому DTO разделов,
их проверки (обязательный и уникальный код, адрес страницы, глубина дерева, защищённые
записи), проверки значений и журнал — те же, что в панели. Журнал подписывает правку
«Ivan · API «1С»», а свойства «Внешний источник» (`isExternal`) ключ заполнять может —
из панели их не правят. Создатель ключа удалён или выключен — 403.

Поля записи и свойства — два маршрута панели, две транзакции. Что можно проверить до
записи, проверяется до неё: права, поля, коды свойств и вариантов, привязки, занятый
внешний ID, родитель. Если свойства всё же не легли (их формат проверяет маршрут
значений), запись откатывается вручную: только что созданная удаляется (в журнале видно
создание и удаление), у правленой возвращаются прежние поля. Иначе запись осталась бы без
внешнего ID, и следующий обмен завёл бы дубль.

Запись ищется **запросом к базе по индексу** (`write/record-lookup.service.ts`), а не
чтением списка: по номеру — первичный ключ таблицы раздела, по коду — индексы
`infoblock_*_code`, по внешнему ID — `infoblock_records_external_id`. Время пакета от
размера списка не зависит (замер — [implemented/external-api.md](../implemented/external-api.md)).
Сами маршруты разделов местами читают список целиком: элементы типов контента
и категории при создании и переносе проверяют глубину дерева по всем записям,
а проверка привязок читает целевой список — на деревьях в десятки тысяч записей это
заметно (отбор в базе — отдельная задача).

**Ошибки**: 400 — непонятный параметр, неизвестное свойство, сортировка или домен,
не прошли проверки панели, больше 500 записей в пакете; 401 — нет ключа или он отозван;
403 — «Ключу не разрешена запись в «…»» (нет права записи или список не из разрешённых);
404 — нет списка или записи; 409 — внешний ID уже у другой записи списка, код занят,
запись защищена. Текст ошибок проверок — тот же, что видит панель.

## Интерфейс

«Настройки → API» (`/admin/settings/api`), пункт виден только root
(`components/settings/api/`, `logic/externalApi/`):

- **Доступ** — адрес API, правила (авторизация, что отдаётся, запись, свойства, домены,
  команда `npx openapi-typescript …` для типов сайта, ошибки) и таблица ключей: название,
  ключ маской, права («Чтение» / «Чтение и запись: Товары, Категории» / «…: все списки»),
  создан, последний запрос, «Отозвать» с подтверждением. «Создать ключ» — окно с названием
  и правами: «Чтение» включено всегда, «Запись» — выключена; включили — «Все списки» или
  «Отмеченные» (галочки по разделам «Сайт», «Контент», «Каталог»). После создания — ключ
  с копированием и предупреждением, что больше его не покажут.
- **Документация** — адрес `openapi.json` и «Скачать», ниже Scalar
  (`ApiReference.tsx`, грузится только в браузере). Спецификация читается при каждом
  показе вкладки. В Scalar выключены чат с ИИ, MCP и панель разработчика; светлая тема.

## Правила и ограничения

- Отдаются только активные записи; запись, заведённая черновиком и ни разу
  не опубликованная (`isNew`), — нет. Черновики не видны: только опубликованное.
- Скрытые свойства (`isHidden`) — ни в ответах, ни в спецификации.
- Фасет свойства считается по записям, отобранным поиском и **остальными** полями фильтра.
- Отбор — общий `pageRecords` (`records-page.ts`), в памяти, но **значения читаются
  только нужные** (`ExternalApiService.valuesOf` → `PropertyValuesService.findSome`):
  записи раздела приходят целиком (они лёгкие), а из значений — на отбор только свойства
  фильтра и сортировки, на ответ — только записей страницы, у `items/{id}` — одной записи.
  Все значения списка разом (описания, SEO-тексты) — это секунды на тысячах товаров.
- **Фильтр по привязке сначала идёт в базу**: `filter[car]=922` — запрос по индексу
  `infoblock_values_property_link` (`linkMatches`), и значения читаются уже у найденных
  записей. Это сужение, а не весь отбор: мультидоменное значение чужого домена тоже
  находится, точный отбор для `domain` делает `pageRecords`. Фасет считается по своим
  записям: без фильтра собственного свойства, с остальными привязками — из базы.
  Замер — [implemented/external-api.md](../implemented/external-api.md).
- Данные сайта общие: ключ читает все, чей бы он ни был; пишет — от имени создателя.
- Спецификация (`openapi-spec.ts`) строится из тех же настроек, что и ответы: завели
  свойство или тип контента — оно сразу в документации. Параметр `expand` у `items`
  и `items/{idOrCode}` — массив кодов (`style: form`, `explode: false`, то есть через
  запятую) с перечнем раскрываемых привязок списка; у такой привязки схема значения —
  `Link` или схема записи её списка (у типа контента — `ContentType`). Меню — группы `x-tagGroups`:
  «Сайт» (страницы, домены), «Контент» (типы контента и по пункту на тип), «Каталог»
  (товары, категории); пункт подписан без группы (`x-displayName`), а имя тега —
  с ней («Контент · Новости»), чтобы не совпало с другим списком.
- Методы записи в спецификации видят все; у каждого в описании «**Нужен ключ с правом
  записи в этот список.**» и значок «Запись» (`x-badges`). Тело — схема списка
  `<Схема>Input` (поля записи и свойства по коду с типами и вариантами), у upsert и пакета —
  `<Схема>Upsert` (без `externalId` в `fields`); общие — `LinkInput`, `DomainGroupInput`,
  `WriteResult`.

## Настройки

| Переменная | Назначение |
|------------|-----------|
| `PUBLIC_URL` | внешний адрес панели (`https://cms.example.com`, без `/` в конце): из него `servers` спецификации и полные адреса файлов |

Без `PUBLIC_URL` адрес берётся из запроса (`X-Forwarded-Proto` + `Host`) — верен
и локально, и за прокси, который передаёт эти заголовки (наш nginx передаёт).
`PUBLIC_URL` нужен, когда прокси их подменяет или панель видна снаружи не по тому
адресу, по которому к ней пришли.
