# docs — документация реализованного

Справочник по системе в её **текущем** состоянии. Отвечает на вопрос «как это устроено и
как этим пользоваться», без истории изменений — история в `implemented/`.

Один файл на модуль: `docs/<модуль>.md`.

## Структура файла модуля

1. **Назначение** — что модуль делает, в двух-трёх предложениях.
2. **Модель данных** — таблицы, поля, связи, ограничения.
3. **API** — эндпоинты, параметры, коды ответов, требуемые права.
4. **Интерфейс** — экраны админки и что на них можно сделать.
5. **Правила и ограничения** — инварианты, которые система удерживает.
6. **Настройки** — переменные окружения и параметры, влияющие на модуль.

## Правило актуальности

Документация описывает то, что есть в коде **сейчас**. Меняется поведение — правится
соответствующий раздел в том же заходе. Устаревшая документация хуже отсутствующей:
ей верят.
