# MCP

## Назначение

ИИ-ассистенты (Claude Code, Claude Desktop, Cursor и любые клиенты MCP) читают и правят
записи панели напрямую, без браузера. Сервер MCP встроен в бэкенд: `POST /api/mcp`,
транспорт Streamable HTTP. Ассистент работает **от имени владельца личного токена, со
всеми его правами** и теми же маршрутами, что и экраны панели: всё, чего пользователь
не может в браузере, не сможет и ассистент. Правки видны в истории записи с пометкой
«MCP «название токена»».

В отличие от внешнего API (`/api/v1`, чтение для сайта), MCP — запись для человека
с ассистентом. Это разные двери с разными ключами.

## Модель данных

`mcp_tokens` — личные токены:

| Поле | Что |
|------|-----|
| `id` | номер |
| `userId` | чей токен: ассистент работает от его имени |
| `name` | где стоит токен — «Claude Code — ноутбук» |
| `tokenHash` | SHA-256 токена, hex; уникальный индекс `mcp_tokens_token_hash` |
| `tokenTail` | последние 4 символа — в списке `spm_••••••••3f9a` |
| `expiresAt` | до какого момента работает; `null` — без срока |
| `lastUsedAt` | последний вызов; пишется не чаще раза в минуту |

Сам токен (`spm_` + 24 случайных байта, base64url) в базе не лежит: его показывают один
раз, в ответе на создание. Отозвать — удалить строку.

`mcp_calls` — журнал вызовов инструментов, 30 дней (старое чистится раз в час при записи).
Своими колонками — только то, по чему журнал отбирают: `userId`, `tokenId`, `tool`,
`isChange`, `isError`, `createdAt`. Остальное — одним `details` JSONB:
`{ tokenName, userEmail, what, detail, result, args }` (у `upload_file` содержимое файла
в `args` — только длиной).

## API

### Протокол (`/api/mcp`, `Authorization: Bearer spm_…`)

Маршрут `@Public()` (мимо JWT-гарда) и закрыт `McpTokenGuard`: токен находится по хэшу,
истёкший, отозванный или принадлежащий выключенному/удалённому пользователю — 401
с `WWW-Authenticate: Bearer`. В Swagger панели его нет.

| Метод | Что |
|-------|-----|
| `POST` | JSON-RPC 2.0: одно сообщение или пачка. Ответ — `application/json`; на уведомления — 202 без тела |
| `GET`, `DELETE` | 405: сервер без сессий и без потока SSE |

Методы JSON-RPC: `initialize` (версии протокола `2025-06-18`, `2025-03-26`, `2024-11-05`;
в ответе `instructions` — как работать с панелью), `ping`, `tools/list`, `tools/call`.
Ошибка инструмента — не ошибка протокола: результат с `isError: true` и текстом
«Ошибка 409: …», чтобы ассистент прочитал его и поправился.

Предел тела — 25 МБ (как у nginx) у всех маршрутов, а не обычные 100 КБ: инструменты пишут
маршрутами панели, и правка, принятая `/api/mcp`, не должна упираться в предел панели.

### Инструменты

Список — `mcp/mcp-tools.ts` (описания там же — их читает модель).

| Инструмент | Что делает |
|------------|------------|
| `list_lists` | все доступные списки: ключ, название, дерево ли, включены ли черновики, можно ли создавать |
| `describe_list` | поля записи, свойства по кодам с форматом значения, варианты «Списков» (`id`), куда ведут привязки, свойства из внешнего источника (`isExternal`), правила кода и черновиков |
| `find_records` | страница записей: `search`, `filters` (`{ key, kind, … }`, key — поле или код свойства), `sort`, `order`, `isDraftOnly`, `page`, `pageSize` (20/50/100) |
| `get_record` | одна запись: опубликованная версия + `draft` (если есть; `draft.isNew` — на сайте её ещё нет) |
| `get_history` | история записи, новые сверху (`limit`, по умолчанию 20) |
| `save_record` | создать (без `id`) или изменить: `fields`, `properties` по кодам, `target`: `draft` / `published` |
| `publish_draft` | опубликовать черновик записи |
| `discard_draft` | удалить черновик; запись, заведённую черновиком, — нельзя (409) |
| `delete_record` | удалить запись |
| `upload_file` | загрузить файл (base64) или забрать внешний по `url` в раздел (`sectionId`) или для свойства (`propertyCode` + `list`) |

Доступные списки (`mcp/mcp-lists.ts`): `pages`, `contents`, `content-items.<тип>`,
`products`, `product-categories`, `file-sections`, `files.<раздел>`, `domains`.
Пользователи, роли, хранилища и формы через MCP не видны.

### Панель (`/api/mcp`, JWT)

| Метод | Что | Права |
|-------|-----|-------|
| `GET /tokens` | токены, новые сверху, с email создателя | root — все, остальные — свои |
| `POST /tokens` `{ name, days }` | создать себе; `days` — 30/90/365 или `null` (без срока); в ответе `token` — целиком, единственный раз | любой |
| `DELETE /tokens/:id` | отозвать | свой — любой, чужой — только root (403) |
| `GET /calls` | журнал: `tokenId`, `tool`, `view` (`all`/`changes`/`errors`), `page`, `pageSize` → `{ items, total }` | root — весь, остальные — свои вызовы |

## Как инструменты пишут данные

У MCP нет своих правил записи. `PanelClient` (`common/panel-client.ts`, им же пишет внешнее API) выпускает JWT
владельца токена на минуту и вызывает маршруты панели на своём же порту
(`http://127.0.0.1:$PORT/api/…`): `ListEditGuard`, проверки DTO (`whitelist`),
обязательный и уникальный код, адрес страницы, защищённые записи, журнал — всё срабатывает
так же, как из браузера. В JWT — `via: "MCP «название токена»"`; `historyAuthor` передаёт
его дальше, и журнал пишет автора «Иван · MCP «…»», черновик — «email · MCP «…»».

`save_record` повторяет карточку записи:

| Что | Как |
|-----|-----|
| новая, `published` | `POST` раздела → `PATCH …/values` |
| новая, `draft` | то же, потом черновик `{ isNew: true }` — на сайте записи нет до публикации |
| существующая, `published` | `PATCH` раздела и/или `PATCH …/values`; черновик не трогается |
| существующая, `draft` | черновик = прежний черновик + новые поля и свойства (`PUT …/drafts`) |

Без `target` — в черновик, если в списке черновики включены, иначе в опубликованное.
Поле `externalId` (внешний ID — номер записи в системе-источнике, у всех списков, кроме
файлов) в черновик не идёт: это не содержимое записи, а её номер у источника, — он сразу
уходит с `PATCH …/values` (см. [infoblock-settings.md](infoblock-settings.md)). Записи
в ответах инструментов несут его полем `externalId`.
`publish_draft` — `PATCH` раздела полями черновика, `PATCH …/values` его свойствами,
`POST …/publish`. У списка, ставшего деревом настройкой (товары), родитель уходит
со значениями, а не в раздел.

## Интерфейс

«Настройки → MCP» (`/admin/settings/mcp`, всем пользователям):
`components/settings/mcp/` + `logic/mcp/`.

- **Подключение** — адрес сервера, правила; переключатель Claude Code / Claude Desktop
  (`mcp-remote`) / Cursor / другой клиент с готовым текстом подключения; что умеет ассистент.
- **Токены** — одна таблица: название, маска, кто создал, срок (истёкший — красным,
  кнопка «Удалить» вместо «Отозвать»), последний вызов. «Создать токен» — название и срок
  (30 дней / 90 дней / 1 год / без срока); после создания окно показывает токен один раз
  и команду `claude mcp add` с ним.
- **Журнал** — вызовы за 30 дней: время, кто (email и токен), инструмент, что затронуто
  с подробностью, результат; отбор по токену, инструменту и виду (все / изменения / ошибки),
  страницы с сервера.

## Правила и ограничения

- Токен живёт не дольше доступа владельца: выключили пользователя (`isActive: false`)
  или удалили — его токены сразу дают 401.
- Ассистент не меняет настройки и свойства списков, пользователей, роли, хранилища,
  ключи API, токены и резервные копии — инструментов для этого нет.
- `upload_file` — base64 в теле вызова (с учётом nginx, 25 МБ, — файл до ~18 МБ) или `url`:
  тогда файл до 20 МБ скачивает маршрут панели `POST /api/infoblocks/files/import`, во
  внутреннюю сеть он не ходит ([`files.md`](files.md)). Забирать необязательно: в значение
  «Файла»/«Изображения» можно записать сам адрес `"https://…"` — `describe_list` это пишет
  в подсказке к значению.

## Настройки

`PORT` — порт, на котором сервер вызывает сам себя (локально 3402, в контейнере 3010);
`PRIVATE_KEY` — им же подписаны внутренние JWT. Своих переменных у MCP нет.
