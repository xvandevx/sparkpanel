# Товары и категории

Каталог: товары и дерево их категорий. В меню — пункт «Товары» с двумя подпунктами:
«Категории» (`/admin/products/categories`) и «Товары» (`/admin/products`). Оба — списки
нового редактора контента (`components/contentEditorNew/`).

Своих полей у товара и категории минимум — код, название, активность (у категории ещё
родитель). Цену, описание, фото и всё остальное заводят **свойствами списка** в «Настройках».
Категории товару назначают **системным свойством «Категории»**: его заводит сервер, поэтому
связь работает сразу, без настройки.

## Модель данных

Обе таблицы — с `userId`: каталог принадлежит тенанту, как страницы.

### Категории — `infoblock_products_categories`

Модуль `infoblocks/products/categories/`, ключ списка `product-categories`.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | serial | номер категории; он же ключ записи в привязке |
| `userId` | int | владелец |
| `parentId` | int null | родитель в дереве; `null` — корень |
| `code` | string, `''` по умолчанию | символьный код; пустой — кода нет |
| `name` | string | название |
| `isActive` | bool, `true` | выключенная остаётся в админке, но не выводится |
| `sort` | int, `500` | «Сортировка»: чем меньше, тем выше в списке |

### Товары — `infoblock_products`

Модуль `infoblocks/products/`, ключ списка `products`.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | serial | номер товара |
| `userId` | int | владелец |
| `code` | string, `''` по умолчанию | символьный код; пустой — кода нет |
| `name` | string | название |
| `isActive` | bool, `true` | выключенный остаётся в админке, но не выводится |
| `sort` | int, `500` | «Сортировка»: чем меньше, тем выше в списке |

### Категории товара — системное свойство

Своей колонки или таблицы связей у товара с категорией нет. Это **системное свойство**
списка `products`: код `categories`, тип «Привязка к контенту» к списку `product-categories`,
**множественное** — товар лежит в нескольких категориях («Кроссовки» и «Распродажа»).
Значения — в `infoblock_values` (`json` = `{ "listKey": "product-categories", "recordId": "5" }`),
как у любого свойства; механизм — [`infoblock-settings.md`](infoblock-settings.md#системные-свойства).

Свойство заводит сервер по перечню `infoblocks/settings/properties/system-properties.ts`:
при старте — у всех сохранённых настроек списка `products`, а у нового пользователя —
при первом чтении свойств списка. Поменять или удалить его нельзя (замок в настройках).

Категории есть и среди источников обычной «Привязки к контенту» — их можно выбрать
в своём свойстве любого списка (например, страница «Акция» → категория «Распродажа»).

## API

Все маршруты требуют авторизации, `userId` берётся из JWT; чужие записи неотличимы
от несуществующих (404).

| Метод | Путь | Что делает |
|-------|------|-----------|
| `GET` | `/api/infoblocks/products/categories` | категории плоским списком, по сортировке, затем по алфавиту (дерево собирает фронт) |
| `POST` | `/api/infoblocks/products/categories` | завести: `{ name, code?, parentId?, isActive?, sort? }` |
| `PATCH` | `/api/infoblocks/products/categories/{id}` | изменить или перенести; `parentId: null` — в корень |
| `DELETE` | `/api/infoblocks/products/categories/{id}` | удалить пустую категорию (204) |
| `GET` | `/api/infoblocks/products` | товары, по сортировке, затем по алфавиту |
| `POST` | `/api/infoblocks/products` | завести: `{ name, code?, isActive?, sort? }` |
| `PATCH` | `/api/infoblocks/products/{id}` | изменить: любое подмножество тех же полей |
| `DELETE` | `/api/infoblocks/products/{id}` | удалить товар вместе со значениями его свойств (204) |

Категории товару пишутся не здесь, а общим маршрутом значений:
`PATCH /api/infoblocks/products/values/{id}` с `values: [{ propertyId, value: [{ listKey, recordId }] }]`.
Журналы — общий маршрут: `/api/infoblocks/history/products`, `/api/infoblocks/history/product-categories`.

Категория приходит с `isBlocked: true`, если на неё ведёт хоть одна привязка: удалить
её нельзя, и редактор вместо корзины показывает замок.

| Ситуация | Ответ |
|----------|-------|
| Удаление категории, к которой привязаны товары | 409 «К категории привязаны товары — сначала уберите её у них» |
| Удаление категории с вложенными | 409 «В категории есть вложенные категории — сначала удалите или перенесите их» |
| Перенос категории в себя или в свою ветку | 400 «Запись не может быть вложена в…» |
| Глубже «Уровней вложенности» списка | 400 «В этом списке не больше N уровней вложенности» |
| Код не из `a-z`, цифр и дефиса | 400 |
| Привязка к несуществующей категории | 400 «Привязанная запись не найдена: product-categories/…» |

## Интерфейс

- **Категории** — дерево на редакторе контента: «Добавить категорию», карточка с полями
  «Название», «Код», «Родитель», «Активность», «Сортировка». Категория с товарами — с замком вместо корзины.
- **Товары** — плоский список: «Добавить товар», карточка с полями «Название», «Код»,
  «Активность», «Сортировка» и системным свойством «Категории» — выбор нескольких категорий из списка.
  Свойства, заведённые в «Настройках», встают в карточку сами.

Раздел закрывает в настройках списка только то, без чего он перестаёт быть собой: код списка
(`products`, `product-categories`) и у товаров — «Уровней вложенности» = 1 (родителя товару
хранить негде, группируют его категориями). Остальное — обычные настройки: глубина дерева
категорий (по умолчанию без предела), символьный код (по умолчанию необязательный), мета записей.

## Правила и ограничения

- Удаляется только **пустая** категория: без привязанных товаров и без вложенных категорий.
  Сносить ветку целиком или молча отвязывать товары — не то, чего ждут от корзины.
- Удаление товара стирает значения его свойств (`DELETE` значений по ключу записи) —
  в том числе привязки к категориям, и категория освобождается.
- Занятость категории ищется **по значениям**, а не по свойству «Категории»: привязать
  её можно и своим свойством другого списка. Номер категории сквозной, поэтому значения
  других пользователей под ним не встретятся.
- Обязательность и уникальность символьного кода задаёт настройка списка и проверяет
  карточка; сервер проверяет только формат.
- Предел вложенности категорий проверяется при создании и переносе — всей веткой
  и при переносе в корень тоже.
