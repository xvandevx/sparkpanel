# Страницы сайта

Раздел `/admin/pages`: дерево страниц сайта. Страница в корне с пустым адресом — **главная**,
и таких может быть несколько: по одной на домен, на A/B-тест и так далее. Внутрь любой
страницы добавляются страницы любого уровня вложенности.

Своих полей у страницы только стандартные — название, код, активность, сортировка и место
в дереве. **Адрес** — системное свойство списка «Адрес» (код `url`), его сервер заводит сам;
всё остальное, **включая текст страницы**, задаётся **свойствами списка** в «Настройках»:
поле модели это поле, которое нельзя завести и убрать из админки, и держать в нём контент
значило бы сделать страницу особой сущностью. Она ей не является — это обычный список
редактора контента.

Раздел построен на универсальном редакторе контента — см. [`docs/content-editor.md`](content-editor.md).

## Модель данных

### `infoblock_pages` — страницы

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `SERIAL` | порядковый номер, он же идентификатор в адресе админки |
| `userId` | `INTEGER` | владелец; изоляция данных идёт по нему |
| `parentId` | `INTEGER \| null` | родитель; `null` — страница в корне сайта |
| `sort` | `INTEGER` | «Сортировка»: порядок среди соседей, по умолчанию 500 |
| `code` | `STRING` | символьный код записи, как у любого списка; к адресу не относится, может быть пустым |
| `name` | `STRING` | название для админки, на сайт не выводится |
| `isActive` | `BOOLEAN` | неактивная остаётся в админке, но не показывается на сайте |

Ни адреса, ни текста в таблице нет: они лежат в значениях свойств списка
(`infoblock_values`) — адрес в системном свойстве «Адрес» (`url`, строка), текст
в свойстве, заведённом в «Настройках» (например, «Текст страницы», тип «HTML»).

**«Адрес»** — сегмент адреса (`about`); пустой — главная, адрес `/` (только в корне).
Системное (`PAGE_URL_PROPERTY` в `system-properties.ts`): через «Настройки» его не удалить
и не переделать. Правила сегмента проверяет раздел страниц, когда значения сохраняют
(`checkUrl` — проверка значений раздела, см. [`docs/infoblock-settings.md`](infoblock-settings.md#проверки-значений-разделом)):
уникальности индексом здесь не добиться — значения лежат в общей таблице.

Индексы: `userId`, `parentId`. На `code` индексов нет: это обычный символьный код,
его обязательность и уникальность — настройка списка («Символьный код записей»).

**Полный адрес страницы** в базе не хранится — его собирает сервер из значений «Адреса»
по цепочке родителей (`pagePaths` в `pages.service.ts`) и отдаёт полем `path` у каждой страницы: `/`, `/about`,
`/about/team`. Пустой сегмент в цепочке пропускается, поэтому страницы под главной
получают адреса от корня сайта. По `path` таблица ищет и сортирует.

### `history` — журнал изменений

Общий на все разделы панели (`entity` = `pages`, `entityId` = идентификатор записи строкой).
Описан в [`docs/content-editor.md`](content-editor.md#журнал-изменений).

## API

Все маршруты требуют авторизации, `userId` берётся из JWT.

| Метод | Путь | Что делает |
|-------|------|-----------|
| `GET` | `/api/infoblocks/pages` | плоский список страниц |
| `GET` | `/api/infoblocks/pages/history?limit&offset` | общий журнал изменений раздела |
| `GET` | `/api/infoblocks/pages/:id` | одна страница |
| `GET` | `/api/infoblocks/pages/:id/history` | история изменений страницы |
| `POST` | `/api/infoblocks/pages` | создать; без `parentId` страница встанет в корень сайта |
| `PATCH` | `/api/infoblocks/pages/:id` | изменить страницу; `parentId: null` — перенос в корень |
| `DELETE` | `/api/infoblocks/pages/:id` | удалить вместе со вложенными |

`GET /api/infoblocks/pages/history` объявлен **до** `GET /api/infoblocks/pages/:id` — иначе Nest примет `history`
за идентификатор.

Тело `POST`/`PATCH` — `parentId`, `code`, `name`, `isActive`, `sort`; адреса в нём нет:
«Адрес» карточка шлёт вторым запросом, значениями свойств
(`PATCH /api/infoblocks/pages/values/:id`). Ответ — страница с `path`.

Коды ответов: `400` — недопустимый перенос, адрес не того формата, пустой адрес
у вложенной страницы или у соседней страницы уже такой адрес (при сохранении «Адреса»
или при переносе), `404` — страницы нет.

## Интерфейс

Экран на новом редакторе контента (`components/pages/PagesScreen.tsx`): таблица-дерево
и карточка записи справа.

- **Таблица**: ID, название, адрес (`path` с сервера — по нему ищут и сортируют),
  активность, сортировка и кнопки строки.
- **Карточка**: «Название», «Код» (если включён в настройках списка), «Родитель» — выбор
  деревом, «Активность», «Сортировка», системное свойство «Адрес» — сегмент с подсказкой
  «пусто — главная, иначе адрес складывается по дереву»; дальше свойства списка по вкладкам.
- **Закрыто разделом** в настройках списка: код списка (`pages`) и уровни вложенности
  (дерево без предела). Символьный код записей выбирают как у любого списка; по умолчанию
  он необязательный.

## Правила и ограничения

- **Главных может быть несколько.** Отдельного признака «главная» нет: главная — это
  страница в корне с пустым адресом. Их разводят домены, A/B-тесты и прочее.
- **Адрес** — строчные латинские буквы, цифры и дефис между ними (`PAGE_CODE_PATTERN`).
- **Адрес уникален среди соседей** — и среди корневых тоже: их общий «сосед» это корень
  сайта. Из правила выведен только пустой адрес — это и есть несколько главных.
- **Пустой адрес — только в корне.** У вложенной страницы без адреса он совпал бы
  с родительским. Проверяется и сохранение «Адреса», и перенос страницы (смена `parentId`):
  адрес сверяется с новыми соседями, иначе перенос главной в чужую ветку проходил бы
  без проверки.
- **Новая вложенная страница без адреса — до второго запроса.** Адрес приходит значениями
  свойств после создания записи, поэтому между двумя запросами (или если второй не дошёл)
  вложенная страница существует с пустым адресом. Известная дыра.
- **Порядок** — по «Сортировке», затем по номеру.
- **Удаление уносит поддерево** — в транзакции; каждая удалённая страница попадает
  в журнал отдельной записью, значения свойств удалённых страниц стираются.
- **Страницу нельзя перенести внутрь собственной ветки** и нельзя сделать родителем самой себе.

## Настройки

Своих переменных окружения у раздела нет. Схема приводится к моделям при старте
(`synchronize: true`), отдельных миграций нет.
