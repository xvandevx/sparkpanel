# Домены сайта

Имена хостов, на которых работает сайт. Живут в левом меню «Настройки» → «Домены»
(`/admin/settings/domains`), рядом с [«Настройками сайта»](settings.md): дерево на новом
редакторе контента — в корне домены, под каждым его поддомены. Доменов сколько угодно, поддоменов у каждого тоже.

Домены **общие на весь сайт**, как и остальные настройки: владельца у строк нет, все
пользователи панели видят и правят одно и то же.

## Модель данных

### `infoblock_domains` — домены и поддомены

Модуль `backend/src/infoblocks/domains/`: домены — список редактора контента (ключ
`domains`), а все такие списки живут в `infoblocks/`, хотя показывается этот в настройках.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `SERIAL` | номер домена — ключ записи у редактора и у значений свойств |
| `parentId` | `INTEGER \| null` | домен, поддоменом которого запись является; `null` — сам домен |
| `name` | `STRING` | имя без протокола и пути: у домена — целиком (`farkop.ru`), у поддомена — только его часть (`ekb`) |
| `isActive` | `BOOLEAN` | неактивный домен остаётся в панели, но сайт на нём не работает |
| `sort` | `INTEGER`, по умолчанию 500 | «Сортировка»: чем меньше, тем выше в списке |

Индексы: `infoblock_domains_parent_name` (`UNIQUE (parentId, name)` — поддомены одного
домена с разными именами) и `infoblock_domains_root_name` (`UNIQUE (name) WHERE parentId
IS NULL` — домены между собой).

**Запись хранит то, что набрали.** Полный адрес (`ekb.farkop.ru`) не хранится — его
складывает сервер из имён по цепочке родителей (`domainAddresses`, `domains/domain-name.ts`)
и отдаёт полем `address`. Переименовали домен — адреса его поддоменов поменялись сами,
переписывать нечего; перенесли поддомен к другому домену — тоже.

Остальное о домене — регион, счётчик, robots.txt, стартовая страница — **свойства списка**
`domains` в его «Настройках» ([`infoblock-settings.md`](infoblock-settings.md)). Список общий
(`isShared`), поэтому и свойства одни на всех: настройки лежат под владельцем `0`.

## API

Все маршруты требуют авторизации; домены при этом одни на всех.

| Метод | Путь | Что делает |
|-------|------|-----------|
| `GET` | `/api/infoblocks/domains` | все домены и поддомены плоским списком, по сортировке, затем по алфавиту, с полным `address`; дерево собирает фронт |
| `POST` | `/api/infoblocks/domains` | добавить; с `parentId` — поддомен |
| `PATCH` | `/api/infoblocks/domains/:id` | правка и перенос; только присланное, `parentId: null` — вынести в корень |
| `DELETE` | `/api/infoblocks/domains/:id` | удалить домен без поддоменов; вместе с ним стираются значения его свойств |

Коды: `400` — неверное имя или глубже предела вложенности, `404` — домена (или родителя)
нет, `409` — домен с таким адресом уже есть / у домена есть поддомены.

### Имя и адрес

1. **Нормализация в DTO**, до проверки формата: убираются пробелы, регистр, протокол,
   путь, параметры. `HTTPS://Farkop.ru/catalog?x=1` станет `farkop.ru` — адрес обычно
   копируют из адресной строки, и отказывать из-за `https://` незачем. Больше имя
   не меняется: что набрали, то и сохранено.
2. **Имя поддомена — только его часть.** Набрали под `farkop.ru` полное `ekb.farkop.ru` —
   `400` «У поддомена указывается только его имя: ekb, без .farkop.ru»: иначе адрес вышел
   бы `ekb.farkop.ru.farkop.ru`.
3. **Сложенный адрес — имя хоста** (`DOMAIN_NAME_PATTERN`): латинские буквы, цифры
   и дефисы, точки между частями, необязательный порт в конце (`localhost:3400`). Поддомен
   с портом (`shop:80` → `shop:80.farkop.ru`) не пройдёт.
4. **Адрес уникален на весь сайт** — проверяет сервис, по адресам всех записей после
   правки (`duplicateAddress`): домен `ekb.farkop.ru` рядом с поддоменом `ekb` у `farkop.ru`
   не встанет, и переименование домена не пройдёт, если адрес хоть одного его поддомена
   совпадёт с чужим. Одинаковые имена у поддоменов разных доменов (`www` у двух доменов) —
   не повтор. Индексы держат от гонки частые случаи.

## Интерфейс

Экран — `components/settings/DomainsScreen.tsx` (страница `pages/admin/settings/domains.tsx`),
Api редактора — `logic/settings/domainsApi.ts`, сеть — `api/domains.ts`. Раздел отдаёт
редактору Api и описание полей, остальное редактор делает сам.

- Колонки: «Домен» (дерево: `farkop.ru`, под ним `ekb`; сортировка, поиск), «Адрес»
  (`ekb.farkop.ru`, поиск), «Активность», «Сортировка».
- Карточка: домен, родитель (его добавляет сам редактор), активность, сортировка, ниже — свойства
  списка. Родителем предлагаются только записи, под которые поддомен встанет, не выйдя
  за предел, — то есть сами домены.
- Шапка — как у любого списка редактора: заголовок — имя списка из его «Настроек»,
  кнопка добавления — «Добавить домен». Журнала нет.
- В «Настройках» списка закрыты разделом (`blockedSettings`): код `domains`, уровней
  вложенности 2, без символьного кода записей и без меты.

## Правила и ограничения

- Уровней два: домен и его поддомены. Предел — «Уровни вложенности» списка (по умолчанию 2),
  в интерфейсе закрыт; сервер проверяет его при создании и переносе, всей веткой.
- Домен с поддоменами не удаляется (`409`): сносить их вместе с ним — не то, чего ждут
  от клика по корзине. Сначала удаляют или переносят поддомены.
- Вынесли поддомен в корень — он становится доменом со своим коротким именем (`ekb`):
  имя не дописывается.
- Править может любой вошедший — отдельного права нет, как у остальных настроек.
- Изменения в журнал (`history`) не пишутся.
- Удалённый домен вычищается из значений мультидоменных свойств всех списков — из групп
  уникальных значений и из исключений; группа, у которой доменов не осталось, удаляется
  ([`infoblock-settings.md`](infoblock-settings.md)).
- По доменам пока ничего не генерируется (nginx, `server_name`): это справочник в панели.
