# Черновики записей

## Назначение

Правку записи можно сохранить черновиком — тогда она лежит отдельно и в запись
не попадает, пока её не опубликуют. Черновик — это **отложенное сохранение**:
в нём ровно те два тела запроса, которые карточка шлёт по «Сохранить» (поля записи
для маршрута её раздела и значения свойств для `values/`), только изменённое
относительно опубликованного. Публикация — то же самое сохранение, поэтому
проверки раздела, проверки значений и журнал изменений срабатывают как обычно.

Черновики бывают у любого списка редактора контента, кроме пользователей, ролей, доменов, типов контента и файлов, и включаются
галочкой «Черновики» в настройках списка.

## Модель данных

### `infoblock_drafts` — черновик записи

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `SERIAL` | |
| `settingsId` | `INTEGER` | список — строка `infoblock_settings` (у общих списков — владельца `0`) |
| `recordKey` | `STRING` | ключ записи в её разделе (`'108'`) |
| `fields` | `JSONB` | изменённые поля записи — как их принимает `PATCH` раздела: `{ "name": "…", "code": "…" }` |
| `values` | `JSONB` | изменённые свойства — как их принимает `PATCH …/values`: `[{ "propertyId": 250, "value": 208 }]` |
| `isNew` | `BOOLEAN` | запись заведена черновиком и ни разу не публиковалась: на сайте её нет |
| `authorId`, `authorEmail` | | кто сохранил черновик последним — из JWT |
| `createdAt`, `updatedAt` | | `updatedAt` — когда черновик сохранили последний раз |

Индекс `infoblock_drafts_settings_key` — `UNIQUE (settingsId, recordKey)`: черновик
у записи один, повторное сохранение правит его же.

Таблицы разделов и `infoblock_values` черновика не видят: в них всегда
**опубликованная** версия. Запись «только в черновике» (`isNew`) — обычная строка
в таблице раздела (номер нужен ей с самого начала), отличает её только черновик
с `isNew = true`.

Модель зарегистрирована в модуле настроек (`InfoblockSettingsModule`) и приходит
оттуда модулю черновиков и модулю значений.

### Настройка списка

`infoblock_settings.isDraftEnabled` — «Черновики», по умолчанию выключено. Наружу
в настройках ещё `hasDrafts`: бывают ли у списка черновики вообще (у `users`, `roles`,
`domains`, `contents` — устройство панели и сайта, а не контент: пользователи, роли,
домены и типы контента (структура разделов; у элементов типа черновики есть); у `file-sections`, `files`, `property-files` —
файл заменяют загрузкой; `isDraftless` в `infoblock-kinds.ts`). У таких списков сервер
держит `isDraftEnabled = false`, что бы ни прислали, а их экраны закрывают переключатель
в окне настроек (`blockedSettings.isDraftEnabled: false`, «Задано разделом»). Пока в списке
есть черновики, выключить настройку нельзя — `409`.

## API

Модуль `infoblocks/drafts/`. Маршрут — `infoblocks/drafts/:listKey`, а не
`infoblocks/:listKey/drafts`: у разделов свои маршруты `infoblocks/<раздел>/:id`,
и «drafts» на месте номера ушёл бы разделу. Правка списков из управления панелью
(пользователи, роли) — только `root` (`ListEditGuard`).

| Метод | Путь | Что делает |
|-------|------|-----------|
| `GET` | `/api/infoblocks/drafts/:listKey/:recordId` | `{ recordId, draft }` — черновик записи или `null` |
| `PUT` | `/api/infoblocks/drafts/:listKey/:recordId` | сохранить черновик целиком: `{ fields, values, isNew? }`. `400`, если в списке черновики выключены. `isNew` учитывается только у первого черновика записи |
| `DELETE` | `/api/infoblocks/drafts/:listKey/:recordId` | удалить черновик — запись возвращается к опубликованному. `409` у записи «только в черновике»: её удаляют целиком |
| `POST` | `/api/infoblocks/drafts/:listKey/:recordId/publish` | снять черновик после публикации: поля и значения к этому моменту уже записаны маршрутами раздела и значений |

Значения в черновике сервер не проверяет — проверит публикация.

**Страница таблицы** (`GET /api/infoblocks/records/:listKey`) знает про черновики:

- ищет, фильтрует и сортирует по записям **с черновиком поверх** (`withDrafts`
  в `records-page.ts`): номер и родитель — опубликованные, дерево строится по ним;
- отдаёт опубликованные записи и значения, а рядом — `drafts` (черновики записей
  страницы) и `draftsCount` (сколько черновиков во всём списке);
- `isDraft=true` — вид «Черновики»: только записи с черновиком, плоским списком.

Удалили запись — её черновик уходит вместе со значениями
(`PropertyValuesService.remove`).

## Интерфейс

Редактор контента (`components/contentEditorNew/drafts/`), когда в настройках
списка включены «Черновики»:

- **Шапка списка** — «Все записи / Черновики N / История изменений».
- **Таблица** показывает черновик поверх опубликованного (название, ячейки свойств).
  У названия — метка «Черновик» или «Только черновик» (пунктир, перечёркнутый глаз).
  В строке с черновиком — значок «Опубликовать черновик», в плавающей панели отмеченных
  строк — «Опубликовать».
- **Карточка** — в шапке переключатель «Черновик / Опубликовано», от него зависит
  главная кнопка:
  - «Черновик»: опубликованное, поверх — черновик. Кнопка «Сохранить черновик»;
    над вкладками блок черновика — когда и кем сохранён, «Удалить черновик»,
    «Опубликовать черновик». Публикуется только **сохранённый** черновик: пока его нет
    или в карточке есть несохранённые правки, кнопка закрыта (подсказка — почему).
    Поля и вкладки, которые черновик меняет, отмечены точкой.
  - «Опубликовано»: версия на сайте. Кнопка «Опубликовать» сохраняет сразу, мимо
    черновика; черновик при этом не меняется (подсказка над вкладками).
  - «Отменить» (появляется, когда есть правки) возвращает поля к показанной версии —
    черновику или опубликованному — и карточку не закрывает.
  - Открывается в «Черновике», если черновик есть или запись новая, иначе
    в «Опубликовано». С несохранёнными правками версию не переключить.
  - Новая запись в «Черновике» заводится как обычно и сразу помечается `isNew` —
    в таблице «Только черновик», «Опубликовано» у неё недоступно, удалить черновик
    нельзя — только запись целиком.

## Правила и ограничения

- Черновик хранит только отличающееся от опубликованного; сохранили без отличий —
  черновик остаётся пустым, его можно опубликовать или удалить.
- Публикуется сохранённый черновик — из карточки и из таблицы одинаково: поля черновика
  частичным `PATCH` раздела (если они есть), свойства — значениями, потом `…/publish`.
  Несохранённое в карточке не публикуется. Не прошло сохранение — черновик остаётся.
- Публикация из «Опубликовано» черновик не трогает.
- Родитель, изменённый в черновике, в таблице не применяется: запись переедет в другую
  ветку с публикацией.
- Сайта (внешнего API) пока нет. Когда появится: боевой режим читает только опубликованное
  и пропускает записи с `isNew`, предпросмотр накладывает черновики той же `withDrafts`.

## Настройки

Переменных окружения нет; включение — галочка «Черновики» в настройках списка.
