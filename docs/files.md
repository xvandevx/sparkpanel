# Файлы

Раздел `/admin/files`: картинки и документы сайта, разложенные по **разделам** — дереву,
как у страниц. И разделы, и файлы раздела — **списки редактора контента**, поэтому живут
в `infoblocks/`. Сами файлы лежат во встроенном хранилище — папке на диске рядом с панелью —
или во внешнем S3 из [настроек](settings.md); в базе — карточка файла.

Файлы попадают сюда двумя путями: их загружают в раздел здесь же или прямо из карточки
записи, через свойство «Файл» или «Изображение» ([`infoblock-settings.md`](infoblock-settings.md)).
Файл из карточки записи раздела не получает — он помнит свойство, через которое его
загрузили, а «Файлы» показывают по разделу на каждое такое свойство. В списке файлов
видно, какая запись выбрала файл.

Изображение от прочих файлов отличается **только MIME-типом** — отдельной сущности нет.

## Модель данных

| Модуль | Таблица | Маршрут | Ключ списка |
|--------|---------|---------|-------------|
| `infoblocks/files/sections/` | `infoblock_files_sections` | `/api/infoblocks/files/sections` | `file-sections` |
| `infoblocks/files/` | `infoblock_files` | `/api/infoblocks/files` | `files.<номер раздела>`, `property-files.<номер свойства>` |

### `infoblock_files_sections` — разделы

| Поле | Тип | Что значит |
|------|-----|-----------|
| `id` | serial | номер раздела |
| `userId` | int | владелец |
| `parentId` | int, null | родитель в дереве; null — корень |
| `name` | string | название |
| `sort` | int, по умолчанию 500 | «Сортировка» |

В таблице только разделы, которые завёл пользователь. Наружу раздел отдаётся
с `filesCount` — файлов в самом разделе, без вложенных. Номер в выдаче — **строкой**
(`"29"`): рядом идут разделы свойств и группы, которых в базе нет. Кода у раздела нет:
сайт берёт файл по номеру.

**Разделы свойств и группы собирает сервер при каждой выдаче** (`findAll`,
`sections/section-groups.ts`), из `propertyId` файлов:

- **раздел свойства** — по одному на свойство, через которое загружен хоть один файл:
  номер `property-<номер свойства>`, название — как у свойства, `propertyId`,
  `isReadOnly` и `isBlocked`. Свойство без файлов раздела не даёт; файлов не осталось —
  раздел пропал сам;
- **группа** — по одной на список этих свойств, один уровень: номер `group-<ключ списка>`,
  в названии путь до списка, как в меню панели (`listTitle`, `MENU_PARENTS`):
  «Контент / SEO / Мета-теги по цветам», «Товары / Категории», «Страницы сайта».
  Приходит с `isGroup`, `isReadOnly`, `isBlocked`; переименовали или перенесли тип
  контента — название следом;
- свойство удалили, а файлы остались — раздел «Удалённое свойство #N» без группы:
  оттуда их удаляют.

Сортировка у них 0 — выше разделов. Номера не числа, поэтому маршруты раздела на них
отвечают 404, а положить в них раздел нельзя (`parentId` — число).

**Глубина дерева ограничена** настройкой списка `file-sections` «Уровней вложенности» —
по умолчанию 2. Раздел нельзя завести или перенести так, чтобы его ветка вышла
за предел (400), а карточка таких родителей не предлагает.

### `infoblock_files` — файлы

| Поле | Тип | Что значит |
|------|-----|-----------|
| `id` | serial | номер файла — он же значение свойства у записи и ключ записи в списке |
| `sectionId` | int, null | раздел; null — файл загружен через свойство |
| `propertyId` | int, null | свойство «Файл»/«Изображение», через которое загружен файл; null — файл в разделе |
| `name` | string | имя файла в панели; при загрузке — имя на диске, потом правится |
| `code` | string | код файла — имя в адресе: латиницей, с расширением (`voprosy-i-otvety.pdf`); считается при загрузке и потом не меняется |
| `mimeType` | string | тип; `image/*` — изображение |
| `size` | int | размер в байтах |
| `storageId` | int, null | хранилище, куда файл загружен (`infoblock_storages`); null — встроенное |

**Владельца у файла нет** — файлы общие на сайт, как настройки и хранилища. Разделы
пока остаются у каждого пользователя свои, и класть файл можно только в свой раздел.

**Ни адреса, ни ключа объекта в базе нет** — адрес собирается из ключа и хранилища
(`StorageService.url`): встроенное — `/uploads/<ключ>`, внешнее — публичный адрес
хранилища или адрес/бакет плюс ключ. Храни адрес рядом с ключом, и сменённый публичный
адрес хранилища разошёлся бы с адресами уже загруженных файлов.

Ключ объекта — папки из номера файла плюс код: номер дополняется нулями до 6 цифр
и режется по две — `78` → `00/00/78/voprosy-i-otvety.pdf` (`objectKeyOf`, `file-key.ts`).
На каждом уровне не больше сотни папок, у каждого файла своя: код в ней ни с чем
не столкнётся, случайный хвост не нужен. С 7 знаков — `10/00/000/…`, ключи не совпадают.
Раздела в ключе нет: файл переносят между разделами. Имя в панели от кода не зависит —
переименовали файл, адрес прежний, ссылки в текстах и шаблонах не ломаются; при скачивании
файл называется исходным именем (`Content-Disposition`, записывается при загрузке).

Загрузка — сначала строка в базе (номер нужен для ключа), потом объект; хранилище не
приняло файл — строка удаляется.

### У файлов свойств нет

Файлы раздела — список `files.<номер раздела>` (и `property-files.<номер свойства>`),
но **свойств у файла не бывает**: вид списка помечен `isPropertyless`
(`infoblock-kinds.ts`), и создание свойства у него сервер отвечает 400. Кнопки
«Настройки» на экране файлов нет. Свойства бывают у разделов (`file-sections`).

### Привязка файла к записи

Отдельной таблицы связей **нет**. Запись выбирает файл значением свойства «Файл» или
«Изображение» — строкой `infoblock_values` с номером файла в колонке `number`. Это и есть
привязка: один файл могут выбрать сколько угодно записей, и вторая копия связи не может
разойтись со значением. Список привязок собирает `FileLinksService` по значениям свойств
списков того, кто спрашивает; название записи берётся у её раздела (страницы),
у остальных списков показывается ключ записи.

## API

Все маршруты закрыты JWT.

| Метод | Путь | Что делает |
|-------|------|-----------|
| `GET` | `/api/infoblocks/files/sections` | разделы пользователя плоским списком, впереди — разделы свойств и группы |
| `POST` | `/api/infoblocks/files/sections` | создать раздел: `name`, `parentId` |
| `PATCH` | `/api/infoblocks/files/sections/:id` | переименовать, перенести; 400 — в собственную ветку |
| `DELETE` | `/api/infoblocks/files/sections/:id` | удалить пустой раздел; 409 — в нём файлы или разделы |
| `GET` | `/api/infoblocks/files?sectionId=&propertyId=` | файлы раздела или свойства, свежие сверху, с `url`, `storageName` и `links`; без них — все файлы |
| `POST` | `/api/infoblocks/files/upload` | multipart: `file` и **одно** из `sectionId` / `propertyId`; 413 — больше 20 МБ |
| `POST` | `/api/infoblocks/files/import` | «Забрать в хранилище»: `{ url }` и **одно** из `sectionId` / `propertyId` — сервер скачивает внешний файл и кладёт как загруженный; 400 — адрес не http(s) или из внутренней сети, не скачался, больше 20 МБ |
| `PATCH` | `/api/infoblocks/files/:id` | имя файла (`{ name }`) |
| `DELETE` | `/api/infoblocks/files/:id` | удалить файл: записи его забывают, объект в хранилище уходит |

`:id` у файлов и разделов — только цифры: иначе `sections` и соседние маршруты списков
(`/api/infoblocks/:listKey/values/:recordId`) уходили бы в маршрут номера.

Забирая внешний файл, сервер не ходит во внутреннюю сеть: адрес, который указывает
на loopback, частные сети, link-local (метаданные облака) или CGNAT, — 400, и так же на
каждом шаге переадресации (их до 5, ведёт их сам). Имя — из `Content-Disposition`, иначе
из адреса; тип — из `Content-Type`; ждёт до 30 с (`files/fetch-external.ts`).

Загрузка с `propertyId` запоминает свойство у файла (свойство — своего списка или общего,
иначе 404); раздела под него не заводится. Соответствие файла ограничениям свойства проверяется не здесь, а при сохранении
значения записи — туда же попадает и файл, выбранный из уже загруженных.

## Как файл попадает в браузер

- **Встроенное хранилище:** `браузер → /uploads/<ключ> → панель → файл в папке`.
  Тот же origin, что у панели, адрес относительный. Файл лежит в папке хранилища
  (`UPLOADS_DIR`) тем же путём, что ключ: `00/00/78/voprosy-i-otvety.pdf`. Отдаёт его
  сама панель (`storage/serve-uploads.ts`, `express.static`) — в образе
  [headless](../webSite/headless/README.md) напрямую, локально и на нашем проде через
  nginx (`location /uploads/` → бэкенд). Тип — по расширению, кэш вечный (ключ уникален),
  `Range` (перемотка видео), `ETag` и 304 — как у любой статики. За пределы папки (`..`)
  и в список файлов папки не пускает — 404.
- **Внешнее хранилище:** адрес абсолютный — `публичный адрес/<ключ>` из карточки
  хранилища или, если он не задан, `адрес хранилища/бакет/<ключ>`. Чтение файлов
  открывается в самом хранилище: бакет чужой, панель его не создаёт и прав на нём не меняет.

**Исполняемые типы отдаются вложением** (`file-disposition.ts`): `Content-Disposition:
inline` — только растровым картинкам, `pdf`, видео и аудио, всему остальному `attachment`.
Иначе открытый с origin панели `.html` или `.svg` выполнился бы рядом с cookie сессии.
Встроенное хранилище решает это при отдаче, по расширению файла, и добавляет
`X-Content-Type-Options: nosniff` — браузер не угадывает тип по содержимому; имя при
скачивании — код файла (`otchet.pdf`). Внешнему хранилищу заголовок пишется в объект
при загрузке, по MIME-типу и с исходным именем.

## Интерфейс

| Адрес | Что показывает |
|-------|----------------|
| `/admin/files` | дерево разделов на [редакторе контента](../webSite/frontend/CLAUDE.md) |
| `/admin/files/2` | файлы раздела — тоже редактор контента, плюс крошки и загрузка |
| `/admin/files/property-6` | файлы свойства — то же самое, список `property-files.6`, загрузка уходит со свойством |

- **Разделы.** Шапка урезана через `settings` редактора: только «Добавить раздел» — без
  журнала, «Настроек» и поиска. Колонки: «Раздел», «Файлов», «Сортировка».
  Добавить, переименовать, перенести — карточкой редактора (поля «Название», «Сортировка»
  и «Родитель»).
  Название — ссылка в раздел, в строке есть и значок перехода (`recordPath`).
  **Раздел свойства** (`isReadOnly`) карточки не открывает: ни номера, ни правки, ни
  галочки, вместо корзины замок, «Сортировка» пустая; перейти в него можно.
  **Группа** (`isGroup`) — ещё и без ссылки и перехода, «Файлов» пустое. В крошках раздела
  свойства группа без ссылки: «Файлы / Контент / SEO / Мета-теги по цветам / файл».
- **Файлы раздела.** Над списком — крошки и «Загрузить файлы» (с диска, можно несколько).
  Сам список — редактор контента без шапки: у Api файлов нет `create`, поэтому нет
  и «Добавить запись», журнала и «Настроек» тоже нет. Колонки: превью (`isPreview`;
  картинка по клику открывается на весь экран, остальное — в новой вкладке), «Файл»
  (она и тянется — превью держит свои 72 px; имя — ссылка на файл в новой вкладке, `linkField`), «Привязан к», «Хранилище», «Размер»,
  «Загружен»; поиск — по имени и хранилищу. «Хранилище» — где файл лежит, меткой
  (`isTag`): «Встроенное» или название внешнего (`storageName`; сервер берёт его у хранилища при выдаче, своей
  колонки в базе нет). «Привязан к» — записи, выбравшие файл, по одной на строку
  ссылками «Список · Запись» (свойство не пишется, запись с двумя свойствами — одна):
  ссылка открывает в новой вкладке страницу списка с карточкой записи (`?id=`,
  `recordPagePath`); у списка без своей страницы — просто текст. Поля «Сортировка» у файлов нет: по умолчанию новые сверху.
  Клик по строке — карточка файла: правится имя, свойств у файла нет.
  Корзина удаляет файл.
- **Поле в карточке записи** (свойство «Файл»/«Изображение», `drawer/file/`): выбранные
  файлы с превью и крестиком, «Загрузить», «Выбрать из загруженных» и «Вставить ссылку»,
  под полем — ограничения («JPG, PNG · до 2 МБ · до 1920×1080 px»). Загрузка уходит сразу,
  к записи файл привязывается её сохранением. У одиночного свойства, когда файл уже
  выбран, кнопок нет: сменить файл — убрать прежний крестиком и выбрать другой.
- **Внешний файл в поле** (`ExternalFileRow`): превью по адресу, имя из адреса и метка
  «Внешняя ссылка · сайт». Действия: «Заменить ссылку» (ввод на месте строки, адрес
  проверяется как у сервера — http(s) и расширение), «Забрать в хранилище» (сервер
  скачивает файл в раздел свойства, на месте ссылки встаёт номер файла — сохраните запись)
  и «Убрать ссылку». В таблице у «Изображения» превью по адресу, у «Файла» — имя из адреса.
- **Выбор из загруженных** — шторка поверх карточки: слева разделы деревом
  (с «Все файлы» сверху, разделами свойств и числом файлов у каждого; группа не выбирается), справа файлы раздела с превью —
  картинка увеличивается по клику, — размером и датой; поиск по имени. Открывается на разделе своего свойства, а пока его нет — на «Все файлы».
  У одиночного поля выбор один, у множественного — сколько угодно, «Выбрать (N)».
  У поля изображения в списке только картинки; файлы не того формата или тяжелее
  предела видны, но закрыты, с причиной («формат не подходит, нужен pdf») — та же
  проверка, что сервер сделает при сохранении.

## Правила и ограничения

- Файл лежит ровно в одном месте: в разделе или у свойства, через которое загружен.
  Раздел с файлами или вложенными разделами не удаляется — молча сносить содержимое
  система не станет. Разделы свойств не удаляют и не заводят: они есть, пока у свойства
  есть файлы. Удалили свойство — файлы остаются в разделе «Удалённое свойство #N».
- Один файл может быть привязан к любому числу записей. Удаление файла стирает эти
  значения — висячий номер карточка показать не смогла бы — и значения свойств самого файла.
- Размер одного файла — до 20 МБ (`MAX_FILE_SIZE`; nginx `client_max_body_size 25m`).
- Поле карточки проверяет файл **до загрузки**: изображение ли, формат, вес и разрешение.
  Сервер при сохранении записи проверяет формат, вес и «только изображения» ещё раз;
  разрешение — только карточка: в карточке файла размеров нет.
- Загрузили из карточки и закрыли её без сохранения — файл остаётся в разделе свойства
  без привязок; его видно и можно удалить.
- Хранилище запоминается у файла (`storageId`): переключили хранилище — уже загруженные
  остаются, где были, и удаляются оттуда же. Хранилище с файлами не удаляется.
- Удаление файла убирает объект в хранилище после карточки. Хранилище не ответило —
  карточка всё равно удаляется, объект остаётся (в логе предупреждение). Во встроенном
  хранилище файла уже нет — не ошибка; пустые папки ключей остаются.
- Изображения не обрабатываются: ни конвертации, ни миниатюр.

## Настройки

Встроенное хранилище — одна переменная бэкенда, `UPLOADS_DIR` (шаблон — `backend/.env.example`):

| Где | Папка |
|-----|-------|
| Локально | `backend/uploads` (по умолчанию — `uploads/` в папке запуска бэкенда; в git не попадает) |
| Образ headless | `/data/uploads`, том `uploads` |
| Наш прод | `/data/uploads` в контейнере бэкенда ← `prod/docker/uploads` на сервере |

Бэкапить папку отдельно: копия сайта ([`backups.md`](backups.md)) файлов не содержит.
Перенести папку в S3 и обратно — простое копирование: путь файла и есть ключ объекта.

**Перенос из прежнего MinIO.** Раньше встроенным хранилищем был MinIO (локально —
`webSite/docker/minio`, бакет `copanel-media`). Уже загруженные туда файлы переносятся
в папку одной командой из `webSite/` — временный MinIO на старых данных и `mc mirror`:

```bash
docker run --rm -v "$PWD/docker/minio:/data" -v "$PWD/backend/uploads:/out" --entrypoint sh pgsty/minio:RELEASE.2026-08-04T00-00-00Z -c 'minio server /data --quiet & until mc alias set old http://127.0.0.1:9000 minioadmin minioadmin >/dev/null 2>&1; do sleep 1; done; mc mirror old/copanel-media /out'
```

Внешние хранилища заводятся в «Настройки» → «Хранилища», куда грузить новые файлы —
выбирается в «Настройки сайта», — [`settings.md`](settings.md).
