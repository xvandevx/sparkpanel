# Контент: типы и элементы

Раздел «Контент» — однотипные записи сайта: новости, статьи, акции. В меню — пункт
«Контент» сразу после «Страниц». Он ведёт на «Типы контента» (`/admin/contents`),
из строки типа переходят в его элементы (`/admin/contents/2`). Оба уровня — списки
нового редактора контента (`components/contentEditorNew/`), устроены как «Файлы»:
корень — список, в запись можно перейти. Оба могут быть деревом: «Уровней вложенности»
у каждого списка — обычная настройка, по умолчанию 1 (плоский).

**Тип задаёт имя и код списка своих элементов.** Название типа — имя списка
`content-items.<id>`, код типа — его код, по нему список находит сайт. Пишет их
сервер, когда сохраняют тип (`assignIdentity`); в окне настроек списка имени и кода
нет ни у одного списка, меняются они в карточке типа.

Своих полей у типа и элемента минимум — код, название, активность. Текст, дату, картинку
и всё остальное заводят **свойствами списка** в «Настройках»; у элементов каждого типа
свойства свои — у новостей одни, у статей другие.

## Модель данных

Обе таблицы — с `userId`: контент принадлежит тенанту, как страницы и товары.

### Типы — `infoblock_contents`

Модуль `infoblocks/contents/` — сам раздел, ключ списка `contents`.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | serial | номер типа; он же в адресе `/admin/contents/<id>` |
| `userId` | int | владелец |
| `parentId` | int null | родитель в дереве; `null` — корень |
| `code` | string, обязателен | символьный код — он же код списка элементов |
| `name` | string | название — оно же имя списка элементов |
| `isActive` | bool, `true` | выключенный остаётся в админке, его элементы не выводятся |
| `sort` | int, `500` | «Сортировка»: чем меньше, тем выше в списке |

### Элементы — `infoblock_contents_items`

Модуль `infoblocks/contents/items/` — вложен в раздел. Ключ списка `content-items.<contentId>` —
отдельный список на каждый тип, поэтому и свойства, и настройки, и журнал у каждого
типа свои.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | serial | номер элемента |
| `userId` | int | владелец |
| `contentId` | int | тип, которому принадлежит элемент |
| `parentId` | int null | родитель — элемент того же типа; `null` — корень |
| `code` | string, `''` по умолчанию | символьный код; пустой — кода нет |
| `name` | string | название |
| `isActive` | bool, `true` | выключенный остаётся в админке, но не выводится |
| `sort` | int, `500` | «Сортировка»: чем меньше, тем выше в списке |

## API

Все маршруты требуют авторизации, `userId` берётся из JWT; чужие записи неотличимы
от несуществующих (404).

| Метод | Путь | Что делает |
|-------|------|-----------|
| `GET` | `/api/infoblocks/contents` | типы плоским списком по сортировке, затем по алфавиту (дерево собирает фронт), у каждого `itemsCount` и `isBlocked` |
| `POST` | `/api/infoblocks/contents` | завести: `{ name, code, parentId?, isActive?, sort? }` |
| `PATCH` | `/api/infoblocks/contents/{id}` | изменить или перенести; `parentId: null` — в корень |
| `DELETE` | `/api/infoblocks/contents/{id}` | удалить пустой тип (204) |
| `GET` | `/api/infoblocks/contents/{contentId}/items` | элементы типа плоским списком, по сортировке, затем по алфавиту |
| `POST` | `/api/infoblocks/contents/{contentId}/items` | завести: `{ name, code?, parentId?, isActive?, sort? }` |
| `PATCH` | `/api/infoblocks/contents/{contentId}/items/{id}` | изменить или перенести |
| `DELETE` | `/api/infoblocks/contents/{contentId}/items/{id}` | удалить вместе со значениями свойств (204) |

Значения свойств — общими маршрутами: со страницей таблицы (`/api/infoblocks/records/content-items.{contentId}`) и по записи (`/api/infoblocks/content-items.{contentId}/values/:recordId`).
Журналы — `/api/infoblocks/history/contents` и `/api/infoblocks/history/content-items.{contentId}`.

| Ситуация | Ответ |
|----------|-------|
| Удаление типа, в котором есть элементы | 409 «В типе есть элементы — сначала удалите их» |
| Удаление типа с вложенными типами | 409 «В типе есть вложенные типы — сначала удалите или перенесите их» |
| Удаление элемента с вложенными | 409 «В элементе есть вложенные элементы — …» |
| Код типа уже занят другим списком (`products`, код другого типа) | 409 «Список с таким кодом уже есть» — тип не сохраняется |
| Тип без кода | 400 |
| Перенос в себя или свою ветку | 400 «Запись не может быть вложена в…» |
| Глубже «Уровней вложенности» списка | 400 «В этом списке не больше N уровней вложенности» |
| Элементы чужого или несуществующего типа | 404 «Тип контента не найден» |
| Элемент из другого типа по номеру | 404 «Элемент не найден» |
| Код не из `a-z`, цифр и дефиса | 400 |

## Интерфейс

- **Меню** — пункт «Контент» ведёт на список типов и раскрывается в дерево типов с той же
  вложенностью, что в списке; тип в меню ведёт на свои элементы, открытый подсвечен,
  его предки раскрыты.
- **Типы контента** — список или дерево: колонки «Название», «Код», «Активность», «Сортировка»,
  «Элементов»; «Добавить тип», карточка «Название», «Код» (обязателен), «Родитель» (если
  список — дерево), «Активность», «Сортировка». Из строки (название или стрелка) — переход в тип. Тип с элементами или
  вложенными — с замком вместо корзины.
- **Тип** — крошки «Типы контента / <предки> / <тип>», заголовок — имя типа, под ним список
  элементов: «Добавить элемент», карточка «Название», «Код», «Родитель» (если дерево),
  «Активность», «Сортировка» и свойства из «Настроек». Неизвестный номер в адресе — «Тип контента
  не найден» со ссылкой назад.

Что раздел закрывает в настройках списков:

| Список | Закрыто | Открыто |
|--------|---------|---------|
| `contents` | символьный код записей — «Обязательный» | уровни вложенности, мета, свойства |
| `content-items.<id>` | — | уровни вложенности, символьный код записей, мета, свойства |

## Правила и ограничения

- Удаляется только **пустой** тип: без элементов и без вложенных типов; элемент —
  без вложенных. Сносить ветку целиком — не то, чего ждут от корзины.
- **Имя и код списка элементов пишет сервер**, при каждом создании и правке типа, в той же
  транзакции (`InfoblockSettingsService.assignIdentity`): настроек ещё нет — заводятся.
  Код занят другим списком — 409, и тип не сохраняется. Код уникален среди списков
  пользователя (индекс `infoblock_settings_user_code`), поэтому и коды типов не повторяются.
- Удаление типа стирает значения его собственных свойств и возвращает настройкам его
  списка элементов имя и код по умолчанию (`Элементы`, `content-items-<id>`) —
  код освобождается для нового типа. Сами настройки (свойства, вкладки) остаются в базе:
  номер типа не переиспользуется.
- Удаление элемента стирает значения его свойств.
- Предел вложенности проверяется при создании и переносе — всей веткой.
- Обязательность и уникальность символьного кода задаёт настройка списка и проверяет
  карточка; сервер проверяет только формат.
- Элементы пока нельзя выбрать в «Привязке к контенту»: источники привязки — только
  перечисленные в [`infoblock-settings.md`](infoblock-settings.md).
