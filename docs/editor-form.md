# Форма, описанная данными

Общий слой форм панели: экран перечисляет **поля и группы данными**, а разметку —
подписи, раскладку, контролы — рисуют общие компоненты. Поэтому форма выглядит
одинаково и в шторке [редактора контента](content-editor.md), и на отдельных экранах
вроде [«Настроек»](settings.md).

## Состав

```
frontend/
  logic/editorForm/             контракт и состояние формы (без разметки)
    types.ts                    поле, группа, значения, EditorFormValue
    form.ts                     видимость, каскады, проверка, сравнение значений
    variables.ts                подстановка переменных в шаблонах, вставка маркера по курсору
    useEditorFormState.ts       значения, правки, сброс, проверка
    EditorFormContext.tsx       мост: состояние формы → компоненты полей
  components/editorForm/        разметка
    EditorForm.tsx              все видимые группы подряд
    fields/                     поле, группа, переменные шаблона, ссылки
```

Редактор контента сидит на этом же слое: его `useEditorState` держит форму через
`useEditorFormState`, а группы раскладывает по вкладкам сам.

## Поле

Поле описывается данными (`EditorFieldDef`), а не разметкой:

| Свойство | Что задаёт |
|----------|-----------|
| `key` | ключ значения; плоская строка, в том числе с точкой (`props.title`) |
| `label`, `note`, `placeholder` | подпись, пояснение под полем, подсказка в поле |
| `type` | `text`, `textarea`, `html`, `richtext`, `number`, `switch`, `select`, `tags`, `file`, `media`, `table`, `password`, `links`, `readonly` |
| `required` | значение обязательно |
| `options` | для `select`: список значений или функция от значений формы; у варианта может быть `group` |
| `rows` | для `textarea` и `html`: высота |
| `multiple` | значение становится массивом. `select` — несколько вариантов, `media` — несколько файлов медиатеки, `file` — несколько файлов с диска; у `text`, `textarea`, `html`, `richtext` и `number` — список полей со строками «Добавить значение» и «Убрать» |
| `nullable` | поле можно оставить пустым — значение `null`: у `number` пусто вместо 0, у `select` выбор сбрасывается крестиком |
| `min` | для `number`: нижняя граница; не задана — 0 |
| `media` | для `media`: какие файлы подходят — `imagesOnly`, `formats`, `maxSizeMb`, `maxWidth`, `maxHeight` |
| `table` | для `table`: `{ columns, headers }` — столбцы и их заголовки; строки добавляются в самом поле |
| `variables` | поле — шаблон: список переменных, предпросмотр, проверка |
| `links` | для `links`: ссылки; не задан — список ещё загружается |

И три необязательные функции от текущих значений формы:

- `hidden(values)` — поля нет при таких значениях (шаблон меты у статичной страницы,
  список поддоменов при снятой галочке);
- `disabled(values)` — поле видно, но не редактируется (код главной страницы);
- `onChange(value, values)` — каскад: правка поля меняет и соседние значения
  (код → пересчёт адреса страницы);
- `validate(value, values)` — проверка перед сохранением: текст ошибки или `null`.
  Сами правила — чистые функции раздела (`logic/<feature>/`), форма их только вызывает.

`tags` — список строк: значение поля массив, значения вводят по одному (Enter, запятая
или пробел заканчивают ввод). Так задаются поддомены в «Настройках».

`file` — выбор файлов с диска: клик или перетаскивание, значение поля — массив `File`.
Поле нужно там, где **запись заводится самим файлом**: в [медиатеке](files.md) сохранение
формы с таким полем и есть загрузка. Сам файл никуда не уходит, пока форму не сохранили, —
отправляет его раздел в своей функции `save`, а не поле.

`html` — разметка: тот же многострочный ввод, что `textarea`, но моноширинным шрифтом.

`select` с вариантами по группам (`group`) рисует их группами; длинный (больше 8) или
сгруппированный список ищется по подписи. Так выглядит «Привязка к контенту» в
[свойствах записей](list-settings.md).

`richtext` — визуальный редактор разметки (Quill), значение — HTML. Подгружается только
в браузере, после монтирования.

`media` — файл медиатеки: значение — номер файла (массив при `multiple`). Файл выбирают
из медиатеки (поиск, фильтр по разделу) или загружают с диска — он ложится в выбранный
раздел медиатеки. С `media`-ограничениями неподходящие файлы видны, но не выбираются,
а разрешение картинки проверяется, загрузив её. Медиатека перечитывается при каждом
открытии окна выбора.

`table` — сетка: столбцов столько, сколько в `table.columns`, строки добавляет и убирает
сам редактор записи («Добавить строку»); значение — строки ячеек `string[][]`. Заголовки
столбцов (`table.headers`) рисуются шапкой, если задан хотя бы один. Обычная
проверка `required` пустую таблицу не поймает (это массив) — для этого `validate`
(`isTableEmpty` из `logic/editorForm`).

`links` — список ссылок только для чтения. **Значения у поля нет**: ссылки приходят
в описании поля (`links`), как `options` у списка, — раздел пересобирает описание, когда
они загрузятся. Пустой список показывает `placeholder`. Ссылки открываются в новой
вкладке: несохранённые правки формы не теряются.

`password` — ввод скрыт точками. Поле всегда открывается пустым: наружу пароль не отдаётся
никогда, поэтому показать в нём «текущее значение» нечего — это поле для нового пароля.
Пустым его оставляют, когда менять не нужно; решает это раздел своей функцией `validate`
(см. «Пользователи»).

Поля собираются в группы (`EditorFieldGroup`): заголовок, пояснение и ключи полей.
Группа скрывается целиком (`hidden`) или сама собой — когда все её поля скрыты.

## Состояние формы

`useEditorFormState({ fields, groups, read, formKey })`:

- `read()` — откуда взять значения; вызывается при смене `formKey`. Пока ключ тот же,
  набранное в форме **не затирается** обновлением данных вокруг;
- `form` — то, что кладут в `EditorFormProvider`: поля, видимые группы, значения, сеттер;
- `isChanged` — значения отличаются от исходных;
- `validate()` — первая ошибка формы или `null` (скрытые поля не проверяются);
- `reset()` — вернуть значения к исходным;
- `commit(next?)` — принять значения за исходные после сохранения; с аргументом заодно
  перечитать форму (сервер мог нормализовать введённое).

Подключение экрана — провайдер и форма:

```tsx
<EditorFormProvider value={form}>
  <EditorForm />
</EditorFormProvider>
```

## Подстановка переменных

Поле с непустым `variables` — шаблон. Переменная пишется решётками: `#NAME#` — такой
синтаксис не пересекается ни с HTML, ни с обычным текстом описания.

Под таким полем показываются:

- список переменных — клик вставляет переменную **в позицию курсора**;
- пример подстановки (значения-образцы из `EditorVariable.sample`);
- предупреждение о переменных, которых нет в списке допустимых — почти всегда это опечатка.

Неизвестная переменная сохранять не мешает и **остаётся в тексте как есть**: пустая строка
вместо неё скрыла бы ошибку. Все функции — чистые (`logic/editorForm/variables.ts`):
`extractVariables`, `substituteVariables`, `previewTemplate`, `unknownVariables`, `insertVariable`.
`insertVariable` — частный случай общей `insertToken(text, cursor, token)`.

## Подключение HTML-блоков — удалено

Раздел «HTML-блоки» убран из панели целиком. В отложенном слое формы (`to_delete/`)
ещё лежат `htmlBlocks` у поля и `logic/editorForm/htmlBlocks.ts` — при возвращении
слоя их не возвращают.
