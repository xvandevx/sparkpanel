# Раскладка компонентов (aiAdmin / SparkPanel)

Компоненты во `webSite/frontend/components/` **не сваливаются в одну папку**. Папка экрана —
это модуль со своей внутренней структурой, а не список файлов.

Слои (`pages → components → logic → redux → api`) описаны в
[`webSite/frontend/CLAUDE.md`](../../../webSite/frontend/CLAUDE.md). Этот скилл — только про то,
**как разложить файлы внутри `components/`**.

## Правило

```
components/
  <screen>/               экран или переиспользуемый блок
    index.ts              публичный вход: только то, что нужно снаружи
    <Screen>.tsx          корневой компонент — композиция, без деталей
    <screen>.module.scss  общие стили блока (если нужны)
    <area>/               функциональная часть экрана
      index.ts
      <Component>.tsx
```

**Порог дробления:** больше **4–5 файлов** в папке — выделяем подпапки по смысловым частям
(шапка, таблица, шторка, поля, история), а не по типу файла (`components/`, `utils/`, `hooks/`).

Пример — универсальный редактор контента:

```
components/contentEditor/
  index.ts                     экспортирует только ContentEditor
  ContentEditor.tsx            композиция: шапка + таблица/журнал + шторка
  contentEditor.module.scss    общие стили редактора
  header/    EditorHeader.tsx
  table/     ContentEditorTable.tsx, TableCell.tsx, RowActions.tsx
  drawer/    ContentEditorDrawer.tsx, UnsavedChangesModal.tsx
  fields/    FieldGroup.tsx, EditorField.tsx, VariableTags.tsx, VariablePreview.tsx
  history/   HistoryTable.tsx, HistoryTab.tsx, HistoryJournal.tsx
```

## Что где лежит

| Что | Куда |
|-----|------|
| Корневой компонент экрана | `<screen>/<Screen>.tsx` — только композиция частей |
| Часть экрана (2+ файла) | своя подпапка со своим `index.ts` |
| Стили блока | один `<screen>.module.scss` в корне папки экрана |
| Используется двумя экранами | `components/shared/` |
| Виджет без привязки к домену | `components/ui/` |

## Границы

- **`index.ts` — публичный вход, а не реэкспорт всего подряд.** Наружу отдаём минимум
  (обычно один корневой компонент); внутренняя раскладка остаётся деталью реализации,
  её можно менять, не трогая `pages/`.
- **Подпапки импортируют друг друга через `index.ts`** соседа (`import { FieldGroup } from '../fields'`),
  а не файлом напрямую.
- **Один компонент — один файл.** Если в файле появился второй компонент (ячейка таблицы,
  кнопки строки, модалка) — выносим в свой файл рядом.
- **Корневой компонент не должен разрастаться:** в нём композиция и ничего больше. Разметка
  шапки, строк, модалок живёт в своих файлах.

## Чек-лист (перед готовностью)

1. [ ] В папке экрана не больше 4–5 файлов на уровень; остальное разложено по подпапкам.
2. [ ] У каждой подпапки есть `index.ts`, и соседи импортируют её через него.
3. [ ] `index.ts` экрана отдаёт наружу только нужное страницам.
4. [ ] В файле ровно один компонент; вспомогательные вынесены рядом.
5. [ ] Корневой компонент — композиция, без разметки частей.
6. [ ] Подпапки названы по смыслу (`table`, `drawer`, `history`), а не по типу файлов.
