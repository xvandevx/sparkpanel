# Товары и категории

## 2026-10-12 — раздел «Товары»: категории деревом, товары списком, связь системным свойством

**Что сделано**

- Бэкенд: модули `infoblocks/products/` (таблица `infoblock_products`, `/api/infoblocks/products`)
  и `infoblocks/products/categories/` (`infoblock_products_categories`,
  `/api/infoblocks/products/categories`); ключи списков `products` и `product-categories` —
  в одном файле `product-lists.ts`, они же типы записей журнала.
- Системное свойство «Категории» у `products` (`system-properties.ts`): привязка к контенту
  к списку `product-categories`, множественное.
- Категории — источник «Привязки к контенту» (`LinkTargetsService`: `link-targets`, `link-sources`).
- Виды списков в `infoblock-kinds.ts`: товары — плоские, категории — дерево без предела.
- `parentError` (`values/records-tree.ts`) стал дженериком: категории адресуются номером,
  а не строкой, правило «не в себя и не в свою ветку» то же.
- Фронт: пункт меню «Товары» с подпунктами «Категории» и «Товары» (`config/navigation.ts`),
  страницы `/admin/products/categories` и `/admin/products`, экраны `components/products/`,
  Api разделов `logic/products/`, сетевой слой `api/products.ts`, `api/productCategories.ts`,
  ключи `ListKey.products`, `ListKey.productCategories`.
- Исправлено в общем слое редактора: `recordRules` (`contentEditorNew/settings/blockedSettings.ts`)
  читал сохранённый предел как `settings?.maxDepth ?? 1` — пришедший `null` («дерево без
  предела») превращался в 1, и у дерева, которое раздел не закрывал, в карточке не было поля
  «Родитель». Страниц это не касалось: они закрывают предел сами.

**Ключевые решения**

- **Связь — системное свойство, а не колонка или таблица связей** (так попросил заказчик):
  тот же механизм, что «Роль» у пользователей. Множественное — товар в нескольких категориях
  обычен, а системное свойство пользователь поменять не может: одиночное пришлось бы
  переделывать в коде.
- **`userId` у обеих таблиц** — каталог это контент сайта, как страницы и HTML-блоки;
  общими на панель (как роли) он быть не обязан.
- **Удаляется только пустая категория** (как раздел файлов), занятая привязкой — с `isBlocked`
  (как назначенная роль). Альтернативы — удалять ветку целиком или молча отвязывать товары —
  отклонены: и то и другое меняет данные, которых пользователь не видит в момент удаления.
- **Товар уносит свои значения свойств** (как файл): иначе удалённый товар держал бы
  категорию занятой навсегда.
- **Своих полей минимум** — код, название, активность; цена и прочее — свойствами списка.
  Сортировки (`sort`) нет: редактор её не правит, порядок — по алфавиту.
- **Символьный код не закрыт разделом**: по умолчанию необязательный, правило выбирают
  в настройках списка; сервер проверяет только формат, без уникального индекса — индекс
  не может следовать настройке.

**Не сделано**

- В таблице товаров нет колонки с категориями: значения свойств в строку таблицы не попадают.
  Параллельно идёт работа над настраиваемыми колонками со значениями свойств
  (`infoblocks/settings/columns/`) — когда она закончится, колонку «Категории» можно будет
  включить без правок раздела.
- Отбора товаров по категории на экране нет.
- Нет переходов «категория → её товары» и порядка категорий вручную.

**Проверено**

- `npx tsc --noEmit` во `backend/` и `frontend/`; `jest src/infoblocks/settings` — 45 тестов,
  новые: виды списков товаров, перечень системных свойств, `parentError` с числовыми ключами.
- Сценарий через API на поднятом стеке: системное свойство заведено само (`multiple`,
  `linkList: product-categories`, `isBlocked`); код с заглавными — 400; перенос родителя
  под ребёнка — 400; товару назначены две категории — обе с `isBlocked`; удаление занятой — 409;
  категории есть в `link-sources` и `link-targets`; удаление товара стирает его значения
  и снимает `isBlocked`; удаление родителя с вложенной — 409; пустые удаляются — 204;
  журнал `products` пишет create/update/delete. Тестовые записи удалены (в журнале остались).
- В браузере: меню «Товары → Категории / Товары» с подсветкой, карточка категории с полем
  «Родитель» (после исправления `recordRules`), карточка товара с полем «Категории»,
  в выборе — только категории.
