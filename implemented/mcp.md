# MCP

## 2026-10-31 — сервер `/api/mcp`, личные токены и журнал в «Настройки → MCP»

**Что сделано**

- Бэкенд, модуль `mcp/`:
  - протокол MCP — `POST /api/mcp` (Streamable HTTP без сессий, JSON-RPC 2.0):
    `initialize`, `ping`, `tools/list`, `tools/call`; `GET`/`DELETE` — 405;
  - 10 инструментов: `list_lists`, `describe_list`, `find_records`, `get_record`,
    `get_history`, `save_record`, `publish_draft`, `discard_draft`, `delete_record`,
    `upload_file`;
  - личные токены — таблица `mcp_tokens` (`spm_…`, SHA-256, срок, последний вызов),
    `GET`/`POST /api/mcp/tokens`, `DELETE /api/mcp/tokens/:id`;
  - журнал вызовов — таблица `mcp_calls` (30 дней), `GET /api/mcp/calls`.
- `JwtPayload.via` и `HistoryAuthor.via`: правка ассистента подписана в истории записи
  («Иван · MCP «Claude Code»») и в черновике («email · MCP «…»»).
- `main.ts`: тело `/api/mcp` — до 25 МБ (файл в base64), общий JSON-парсер поставлен явно.
- Фронт: пункт «MCP» в «Настройках» (`/admin/settings/mcp`, всем), вкладки
  «Подключение», «Токены», «Журнал» — `components/settings/mcp/` + `logic/mcp/`,
  `api/mcp.ts`, `redux/action-creaters/mcp.ts`.

Подробности — [`docs/mcp.md`](../docs/mcp.md).

**Ключевые решения**

- **Инструменты ходят в маршруты панели, а не в сервисы разделов.** `PanelClient`
  выпускает JWT владельца токена на минуту и вызывает `/api/…` на своём порту. Иначе
  пришлось бы повторить для MCP гарды, проверки DTO, правила разделов (код, адрес
  страницы, защищённые записи) и сборку «поля + свойства + черновик», которую сейчас
  делает карточка в браузере, — две реализации одного и того же разошлись бы. Цена —
  лишний HTTP-круг внутри процесса, для ассистента незаметный.
- **Протокол написан руками, без `@modelcontextprotocol/sdk`.** Без сессий и потоков
  сервер — это четыре метода JSON-RPC (~100 строк). SDK тянет ESM, `zod` и свежий
  TypeScript, а бэкенд на Nest 9 / TS 4.7 / CommonJS.
- **Права — все права владельца, без выбора инструментов** (по просьбе заказчика:
  выдали токен — ассистент может всё). Ограничение одно: чего владелец не может в панели,
  того не сможет и ассистент.
- **Черновики** (по просьбе заказчика): `get_record`/`find_records` отдают опубликованное
  и `draft` рядом, `save_record` сохраняет в выбранную версию, без указания — как
  настроен список.
- **Свойства по кодам**, а не номерам: модели код понятнее, номера — внутренность
  панели. Незнакомый код или поле — 400 с перечнем известных, а не молчаливый пропуск.
- **Журнал — колонки только для отбора, остальное JSON** (`details`): по замечанию
  заказчика о лишних полях; новому инструменту не нужны новые колонки.
- **Токены — один список с создателем** (по просьбе заказчика). Root видит и отзывает
  все, остальные — свои; токен заводит себе любой пользователь.
- **Токен — отдельный от ключей внешнего API** (`spm_` против `sp_`): ключ сайта — только
  чтение, общий, от root; токен MCP — запись, личный.

**Отступления от задания**

- Подпись в истории — к имени автора («Иван · MCP «…»»), а не отдельной меткой: журнал
  записи берёт имя и email из учётной записи, своей колонки под источник у него нет.
- `upload_file` — только base64; загрузка по ссылке не сделана (сервер ходил бы по
  адресам ассистента, в том числе внутренним).

**Не сделано**

- OAuth для клиентов MCP — только токен в заголовке.
- Инструменты для настроек списков, пользователей, ролей, хранилищ и форм.

**Проверено**

- `npm test -- mcp` — 7 тестов: свойства по кодам ↔ номерам, лишнее поле, слияние
  черновика, фильтр по коду свойства, вид записи с черновиком.
- Вручную через curl на живых данных: `initialize`, уведомление (202), `tools/list`;
  `list_lists` (25 списков, вместе с `files.N`), `describe_list`, `find_records` с фильтром
  по свойству; полный цикл на странице: создание черновиком (`isNew`) → правка черновика →
  `publish_draft` → правка сразу в опубликованное при живом черновике → `discard_draft` →
  `delete_record`; история записи подписана «Ivan · MCP «Проверка MCP»»; товары:
  обязательный код (400), незнакомое свойство (400); файлы: `upload_file` → переименование
  → удаление; чужой список (400), нет записи (404); отозванный токен — 401.
- В браузере: три вкладки, создание токена (окно с токеном и командой один раз), журнал
  с отбором «Ошибки», без предупреждений в консоли. Тестовые токены после проверки отозваны,
  тестовые страница, товар и файл удалены.
- Найдено и исправлено по ходу: свой JSON-парсер для `/api/mcp` отменял общий парсер Nest —
  тела остальных маршрутов приходили пустыми; общий теперь ставится явно.
